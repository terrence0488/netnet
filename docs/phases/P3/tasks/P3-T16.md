# P3-T16: Insights — the first period has no change

Status: todo
Depends on: none
Parallel-safe: yes

## Goal

The first period in a view shows its end value and no change, on the web and through the agent.
Its whole opening value no longer reads as a gain or loss that never happened.

## Context

- Test report issue 11: Insights shows "November 2025 −$8K" for an account that opened at −$8K,
  and "+$500" for a new user's first month. `packages/core/src/periods.ts` takes each change as
  the end value minus the previous period's end, with 0 before the first.
  `get_period_changes` returns `change` = `end_value` for that period (with `change_pct` null), so
  an agent may read it the same way. The averages already leave the first period out.
- PRD J11: never a fabricated row. Architecture §7.4, rewritten: change and % are both null for
  the first period, which has nothing before it to compare with.
- "First" means the earliest period carrying data in the set being shown, after filters and Don't
  Show exclusions.
- **Unchanged:** a holding first valued in a later period still counts toward that period's
  change. Do not widen this task.
- The holding page's period bar chart (J4) runs on the same engine, so its first period gets no
  bar.

## Interface contract

- `core.periods`: `change: number | null` and `changePct: number | null`, both null for the first
  period of the series. Every later period is unchanged.
- The first period has no drivers.
- `get_period_changes`: `change` is nullable in the output schema, and the tool's description says
  why. This is the §7.4 contract as rewritten.
- Insights: the first period's row shows its end value and, where the change would be, a plain
  statement that it is the first period (copy in the design system's voice). Its drill-down says
  there is nothing earlier to compare with.
- Holding chart: no bar for the first period. With only one period, the shared placeholder shows
  as now.
