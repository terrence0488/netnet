# P3-T15: The reminder runs on GitHub Actions schedules

Status: done
Depends on: none
Parallel-safe: yes

## Goal

The three daily reminder runs fire for certain: GitHub Actions schedules call
`/api/cron/reminders`, as the daily sweep and the FX run already do, and `vercel.json` carries no
crons. This must be on production before the first reminders fall due, around 2026-11-14.

## Context

- Test report issue 2. `decisions.md` records that Vercel's scheduler never fired the production
  crons (jobs registered, manual triggers 200, zero scheduled executions in two days), so the
  daily and FX runs moved to GitHub Actions. P3-T5 then put the three reminder entries in
  `vercel.json`. If Vercel still does not fire them, no reminder and no security-email retry ever
  goes.
- Architecture §9.3, rewritten: every scheduled job is a GitHub Actions schedule calling its
  handler with `CRON_SECRET`. §7.10 explains why three runs eight hours apart keep every send in
  the daytime, even when a run starts an hour late.
- `.github/workflows/cron-daily.yml` is the pattern: the repository secret `CRON_SECRET`, the
  repository variable `PUBLIC_ORIGIN`, deliberately no `environment:` (a required reviewer would
  hold every run), and a failure on any status but 200.
- CI's path filter already treats `.github/workflows/cron-*.yml` as workflow-only (no browser
  suite, no preview).
- Clocks were started on deploy day (2026-10-15), hence the 2026-11-14 deadline.

## Interface contract

- `.github/workflows/cron-reminders.yml`: schedules at `0 1 * * *`, `0 9 * * *` and `0 17 * * *`
  UTC, plus `workflow_dispatch`. It calls `GET /api/cron/reminders` with `Authorization: Bearer
  $CRON_SECRET`, prints the handler's response (counts only: check that it carries no personal
  data), and fails on any status but 200.
- `vercel.json`: the `crons` array goes.
- The handler is unchanged. It still refuses a missing or wrong secret with 401.

## Files in scope

- `.github/workflows/cron-reminders.yml` (new)
- `vercel.json`
- Any test that reads `vercel.json` or lists the workflows
- `ops/` notes, if one lists the scheduled jobs
