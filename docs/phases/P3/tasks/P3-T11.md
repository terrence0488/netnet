# P3-T11: Remove undo; Activity is a read-only log

Status: todo
Depends on: none
Parallel-safe: yes

## Goal

Undo leaves the product everywhere: the Ledger, REST, MCP, the web app and analytics. Activity
stays as a read-only log of every change. A mistake is corrected by another change, on the web or
through the agent.

## Context

- The Founder's decision (`docs/phases/P3/feedback.md`, items 1, 2 and 4): undo added too many
  edge cases and too much complexity for what it is worth. Every change moves forward.
- PRD J7, N3, M5 and §3.5, rewritten: the log is a record only; `value_corrected` fires when a value
  is edited or deleted; `value_undone` is gone. Test report issue 5 falls away with it.
- Architecture §6.3 (`audit` without `undoes` and `undone_by`), §6.8 (audit and agent turns), §7.2
  (only `GET /api/activity`), §7.3 (no `undo`), §7.4 (18 tools, no `undo`), §7.5 (no
  `UNDO_CONFLICT`), §7.7 (no `value_undone`).
- **Batches stay.** Activity still shows one agent turn as one group, and `list_activity` keeps
  its `batch_id` filter. Only reverting goes.
- **`row_version` stays** on holdings and values. It is part of the `Holding` and `Value`
  contracts; nothing checks it for conflicts any more.
- Production already holds undo entries (the Founder's and the probe's accounts). Once the
  columns go, each reads as the plain change it made (old → new), which is what it was.
- `apps/api/src/ledger/currency.ts` belongs to P3-T12, which rewrites it. Leave it alone here
  beyond what compiling needs.
- Copy that promises undo: `apps/web/src/routes/agent/Agent.tsx` (two places),
  `routes/connect/Approve.tsx` and `components/AskAgent.tsx`. Each says instead that every change
  the agent makes shows in Activity. Comments that mention undo (`app/Shell.tsx`, `Toast.tsx`,
  `ledger/holdings.ts`, `ledger/taxonomy.ts`) are rewritten to match.
- The prototype is the behavioural reference, so its Activity loses Undo too
  (`docs/02-prototype/app.js`, `docs/02-prototype/tests/func.mjs`). `prototype-notes.md` and
  `design-system.md` were rewritten at triage.

## Interface contract

Removed:
- `Ledger.undo`, and `UndoTarget` and `UndoResult` in `packages/contracts`.
- `POST /api/activity/:entryId/undo` and `POST /api/activity/batches/:batchId/undo`. They answer
  `404 NOT_FOUND` like any unknown route.
- The MCP `undo` tool (`packages/contracts/src/mcp/undo.ts`, `apps/api/src/mcp/tools/undo.ts`).
  The server lists **18 tools**. `list_activity`'s description no longer mentions undo.
- The `UNDO_CONFLICT` error code.
- The `value_undone` event: its schema, and any client or metrics reference. Rows already in
  `analytics.event` stay; nothing writes new ones.
- `ledger.audit.undoes` and `ledger.audit.undone_by`, with their foreign keys, by a migration from
  `pnpm db:generate`. `AuditEntry` loses the matching fields.

Unchanged: `GET /api/activity`, `list_activity {cursor?, limit≤100, batch_id?}`, batching, and the
audit row on every write.

Changed:
- `deleteValue` fires `value_corrected {original_source, age_at_correction}` like `updateValue`
  does, from the web and through the agent. NetNet's own `system` writes fire nothing.

## Done criteria

- [ ] No undo anywhere: no route, tool, Ledger method, error code, event, column, button or copy

      and when. Nothing on it changes data. A former undo entry reads as the change it made
