# P3-T8: The holding page's period bar chart

Status: done
Depends on: P3-T7
Parallel-safe: yes

## Goal

Each holding page grows its second card: a bar chart of that holding's period
changes with a monthly / quarterly / yearly switch and paging, from the same
period machinery as Insights.

## Context

- PRD J4 (the holding's "bar chart of its period changes with a monthly /
  quarterly / yearly switch and paging") is the contract; P3-T7 provides
  `core.periods`, computed locally from the snapshot — no new endpoint.
- Carried periods read as carried, not observed (J11). With fewer than two
  periods carrying data, the chart keeps its place as the same "Need more data"
  placeholder as Home's (J4), never an empty grid or a one-point axis.
- Chart geometry comes from `core.chart`; the components are our SVG over it
  (CONVENTIONS §13, P2-T3's components where they fit). Tokens only.
- P3-T9 builds the Insights screen in the same wave from the same engine. The
  two tasks share nothing new: common needs go through `core`, not through
  each other's components, and each touches only its own route and components.

## Interface contract

- Second card on the P2 holding page. Consumes `snapshot` + `core.periods`
  filtered to this holding; the M/Q/Y switch and paging are local state.
- Bars show per-period change (money); each bar reads its period and figures
  like the P2 trends (hover, tap, drag, arrow keys; a plain swipe still
  scrolls). Carried periods are marked. The placeholder matches Home's sample
  (neutral ink, frosted, no figures or dates, one line saying what makes it
  appear).
- No new analytics events.

## Files in scope

- `apps/web/src/routes/**` (the holding route's new card only)
- `apps/web/src/charts/**`, `apps/web/src/components/**` (only components this
  card needs)
- `e2e/**` for this card
