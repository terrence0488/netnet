# P3-T17: Home — the stale note under Position, and E2E with push

Status: todo
Depends on: none
Parallel-safe: yes

## Goal

On Home the stale note sits directly beneath Position and the push card below it, in every
browser. The end-to-end suite renders Home in a browser that can receive push as well as in one
that cannot, and the taxonomy flake is fixed at its cause.

## Context

- Test report issue 9. CI's headless shell has no `PushManager`, so E2E never renders the push
  card. In a browser that has one (real desktop and Android Chrome), Home reads Position → push
  card → stale note: `apps/web/src/routes/home/Home.tsx` renders `<PushCard />` before
  `<StaleNote>`. Two Home tests fail there: `session_started` also sees `push_prompt_shown`, and
  the stale note sits 140 px below Position.
- P2's rule puts the stale note **directly** beneath Position, because it qualifies the figures
  above it. J12 puts the push card below Position. Both hold with Position → stale note → push
  card (decisions.md, Design).
- Test report issue 12: `e2e/taxonomy.spec.ts:215` (phone) failed once and passed on re-run.
  "Flake" is not a cause: find the race.

## Interface contract

- No API or contract change.
- Home's side column: Position, then the stale note (when anything is stale), then the push card
  (when its rules show it).
- E2E: the Home specs run twice, once with no `PushManager` (as CI's shell) and once with
  `PushManager` and `Notification` stubbed through an init script, permission `default`, so the
  card renders. The event assertions name `push_prompt_shown {entry: home}` where the card shows.
- `taxonomy.spec.ts:215`: the race is named in the report and fixed in the test or the code. No
  retry is added and no test is skipped.
