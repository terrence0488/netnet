# P3-T4: Export and account deletion

Status: done
Depends on: P3-T3 (both extend Settings; ordering only), P3-T5 and P3-T6 (the tables `destroy()` clears)
Parallel-safe: yes

## Goal

The person can take everything away as a file they could rebuild a spreadsheet
from, or delete the account and have every reminder stop at once.

## Context

- PRD J10 is the contract; architecture §7.3 (`exportAll`, `destroy`), §7.2
  (export and account routes), §8 (Deletion), §7.7 (`account_deleted`).
- Stated window: **30 days**, the life of our daily backups. Shown before the
  user confirms.
- Deletion revokes every agent connection, deletes notification endpoints and
  reminder state (P3-T5, P3-T6), and re-keys analytics events to a random id
  (they still count, they no longer point at anyone). It fires
  `account_deleted` and no `push_disabled` (J12).
- The deletion needs a sign-in in the last 10 minutes, else `REAUTH_REQUIRED`.

## Interface contract

- `GET /api/export?format=json|csv` → everything: holdings, types, tags,
  accessibility and the answer behind it, all values with currencies, rates and
  rate dates. JSON is the full bundle. CSV is one flat values table with the
  header: `holding_id,holding_name,kind,type,currency,date,amount,
  base_amount,base_currency,fx_rate,fx_rate_date,fx_source,source,client,
  access,access_reason,tags` (amounts in major units, tags `;`-separated).
  This column list is an additive detail under plan rule 4; list it in the
  report.
- `DELETE /api/account` → `{erasedWithinDays: 30}`. Order inside one operation:
  revoke connections → delete `ledger` rows, identity, sessions, OAuth grants,
  endpoints, reminder state → re-key events → fire `account_deleted`.
- Web: export controls and a deletion flow whose confirm screen states the
  30-day window first. New sections on the P3-T3 Settings route.
