# P3-T20: Insights — the average's percent agrees with its amount

Status: todo
Depends on: none
Parallel-safe: yes

## Goal

Insights' summary line states one average: the mean change over the periods shown, and the same
change as a share of where they started. The percent never rises while the amount falls.

## Context

- Test report issue 2: monthly changes of −$4,000 (−44.4%), +$1,300 (+26%), +$1,000 (+15.9%), $0
  and +$1,000 (+13.7%) read "Averaging −$140 (+2.2%) a month over the last 5 months". Net worth
  fell from $9,000 to $8,300 (−7.8%). `summarisePeriods` (`packages/core/src/period-summary.ts`)
  takes the mean change, which is right, and the mean of the periods' percents, which can
  disagree with it in sign. The prototype (`docs/02-prototype/app.js`, `renderInsights`) averages
  percents the same way, and this task corrects it. PRD J11 and the architecture do not define
  the average. The rule is in `decisions.md` (Holdings, accessibility and packs).
- **The percent:** the mean change as a share of the opening total, `avgPct = (sum of changes ÷
  count) ÷ |opening| × 100`, worked from the exact sum, not from the rounded `avgAbs`. The opening
  total is the end value of the period before the first averaged one, which is `first.endValue −
  first.change`. Its sign is always the amount's, and it uses the same `|previous|` as each
  period's `changePct` (`packages/core/src/periods.ts`). An opening of 0 has no percent. In the
  example: −$140 on $9,000 is −1.6%.
- **The periods averaged:** every period in the set given whose change is not null. Since P3-T16
  the series' first period has a null change, so `summarisePeriods`' `index > 0` filter now only
  drops a ranged view's oldest period (6M, YTD, …), although that period has an earlier one to
  compare with. The prototype counts it. P3-T16's report noted the gap. "Over the last N months"
  counts the periods averaged.
- `get_period_changes` returns no average, so the agent's side is unchanged.

## Interface contract

- `PeriodSummary` (`@netnet/core`): `count` is the number of periods given whose change is not
  null. `avgAbs` is unchanged: the mean change in minor units, half away from zero. `avgPct:
  number | null` is as above, and null when the opening total is 0. `summarisePeriods` is null
  when no period has a change, as now.
- Insights' summary line: "Averaging −$140 (−1.6%) a month over the last 5 months". With no
  percent: "Averaging +$500 a month over the last 2 months". The other summary lines (filtered
  out, nothing tracked, not enough history) are unchanged.
- No REST or MCP change.
