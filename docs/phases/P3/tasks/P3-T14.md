# P3-T14: The probe's refresh token never reaches a log

Status: todo
Depends on: none
Parallel-safe: yes

## Goal

The MCP probe's rotated refresh token is masked before anything could print it, and no workflow
script carries it inline. Run this task first: the token in the latest logs is the live one.

## Context

- Test report issue 4 (security). The "Store the rotated token" steps in
  `.github/workflows/deploy.yml` and `.github/workflows/probe.yml` put
  `${{ steps.*.outputs.refresh_token }}` inside their `run:` script. The runner prints the script
  before its `::add-mask::` line takes effect, so the token is in plain text in the log (deploy
  run #27 shows it). The repository is private, so exposure is limited to people and apps with
  read access. The token grants `ledger.read` and `ledger.write` on the probe account (fictional
  data).
- `scripts/probe.ts` writes `refresh_token=…` to `$GITHUB_OUTPUT`; `scripts/smoke.ts` goes the same
  way through the probe. `ops/probe.md` describes the probe and its one-time setup (F15).
- Step outputs are not masked by GitHub. Only secrets are.

## Interface contract

- `scripts/probe.ts` (and the smoke path) prints `::add-mask::<token>` to stdout before writing
  the token to `$GITHUB_OUTPUT`, whenever `GITHUB_ACTIONS` is `true`.
- Workflow steps pass the token through `env:` (for example `REFRESH_TOKEN: ${{
  steps.probe.outputs.refresh_token }}`) and use `"$REFRESH_TOKEN"` in the script. No `run:`
  script in `.github/workflows/` interpolates a `steps.*.outputs.*` expression that carries a
  token.
- A test fails when a workflow's `run:` block interpolates `refresh_token` through `${{ … }}`.
- `ops/probe.md` says how the token is masked, and the rotate-and-delete steps below.

**Founder steps after merge** (the report repeats them): revoke the probe's connection in NetNet;
re-run `ops/probe.md`'s one-time setup so `PROBE_REFRESH_TOKEN` holds a fresh token; delete the
logs of every deploy and probe run that printed one (Actions → the run → Delete all logs).

## Files in scope

- `ops/probe.md`
