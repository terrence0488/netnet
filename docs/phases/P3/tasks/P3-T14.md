# P3-T14: The probe's refresh token never reaches a log

Status: todo
Depends on: none
Parallel-safe: yes

## Goal

The MCP probe's rotated refresh token is masked before anything could print it, and no workflow
script carries it inline. Run this task first: the token in the latest logs is the live one.

## Context

- Test report issue 4 (security). The "Store the rotated token" steps in
  `.github/workflows/deploy.yml` and `.github/workflows/probe.yml` put
  `${{ steps.*.outputs.refresh_token }}` inside their `run:` script. The runner prints the script
  before its `::add-mask::` line takes effect, so the token is in plain text in the log (deploy
  run #27 shows it). The repository is private, so exposure is limited to people and apps with
  read access. The token grants `ledger.read` and `ledger.write` on the probe account (fictional
  data).
- `scripts/probe.ts` writes `refresh_token=…` to `$GITHUB_OUTPUT`; `scripts/smoke.ts` goes the same
  way through the probe. `ops/probe.md` describes the probe and its one-time setup (F15).
- Step outputs are not masked by GitHub. Only secrets are.

## Interface contract

- `scripts/probe.ts` (and the smoke path) prints `::add-mask::<token>` to stdout before writing
  the token to `$GITHUB_OUTPUT`, whenever `GITHUB_ACTIONS` is `true`.
- Workflow steps pass the token through `env:` (for example `REFRESH_TOKEN: ${{
  steps.probe.outputs.refresh_token }}`) and use `"$REFRESH_TOKEN"` in the script. No `run:`
  script in `.github/workflows/` interpolates a `steps.*.outputs.*` expression that carries a
  token.
- A test fails when a workflow's `run:` block interpolates `refresh_token` through `${{ … }}`.
- `ops/probe.md` says how the token is masked, and the rotate-and-delete steps below.

**Founder steps after merge** (the report repeats them): revoke the probe's connection in NetNet;
re-run `ops/probe.md`'s one-time setup so `PROBE_REFRESH_TOKEN` holds a fresh token; delete the
logs of every deploy and probe run that printed one (Actions → the run → Delete all logs).

## Report (filled by engineer)

Files changed:
- `scripts/probe.ts`: `emitRotatedToken` prints `::add-mask::<token>` first whenever
  `GITHUB_ACTIONS` is `true`, before the token is written to `$GITHUB_OUTPUT` (or, with no
  `$GITHUB_OUTPUT`, printed). Off Actions nothing changes. Header comments updated.
- `scripts/smoke.ts`: header comment only. The smoke path rotates through `emitRotatedToken`,
  so it masks the same way with no code change.
- `.github/workflows/probe.yml`, `.github/workflows/deploy.yml`: each store step takes the
  token as `REFRESH_TOKEN: ${{ steps.<id>.outputs.refresh_token }}` under `env:` and runs
  `gh secret set PROBE_REFRESH_TOKEN --body "$REFRESH_TOKEN"`. The in-script `::add-mask::`
  lines are gone because the script has already masked the token, a step earlier.
- `test/workflows/scan.ts` + `scan.test.ts` (new, `repo` project): scan every `run:` script
  under `.github/` (workflows and any composite action; block, single-line and multi-line
  expressions) and fail on a `${{ … }}` carrying a refresh token, a step/job/needs output
  named for a token, secret, password, credential or database URL, any `secrets.*`, or
  `github.token`. A planted fictional workflow proves what it catches and that `env:`,
  `with:`, job `outputs:` and `if:` are left alone. The sweep of all six workflows found only
  the four lines in `deploy.yml` and `probe.yml`. `ci.yml`'s preview `database_url` already
  goes through `env:`, and its inline `steps.deploy.outputs.url` is a URL.
- `test/probe/probe.test.ts`: the mask comes first, with `$GITHUB_OUTPUT` still empty when it
  is printed, and is the only logged line carrying the token. Without `$GITHUB_OUTPUT` it
  comes before the printed token. With `GITHUB_ACTIONS` unset or `false`: no mask and no
  token in the log. The CLI test runs with `GITHUB_ACTIONS` `true` (only the mask line
  carries the token) and `""` (none does). It used to inherit CI's `GITHUB_ACTIONS=true`.
- `test/smoke/smoke.test.ts`: `checkAuthenticated` on Actions masks before writing.
- `ops/probe.md`: "The token stays out of the logs" (how it is masked, `env:` only, the scan)
  and "If a token reaches a log" (revoke, set up again, delete the logs).
