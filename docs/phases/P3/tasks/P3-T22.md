# P3-T22: The context gives each holding's currency

Status: todo
Depends on: none
Parallel-safe: yes

## Goal

Every holding `get_financial_context` lists says which currency it is held in, whether or not it
has a value yet, so an agent reads each holding's currency from the one summary call (PRD J8).

## Context

- Founder report after P3's approval: asked for the full picture, Claude could not see every
  holding's currency. Today a listed holding's currency appears only inside `value`, so a holding
  without a value (`value: null`) has none. `list_holdings` has every holding's `currency`, but J8
  asks that one summary call be enough to answer.
- `value.currency` stays as it is. A value can be in another currency than its holding
  (`record_values` takes an optional `currency`; `apps/api/src/ledger/values.ts` defaults it to
  the holding's), so the holding's `currency` and its value's `currency` are separate facts.
- Architecture §7.5 already shows the new key: each holding is
  `{id, name, type, tags, currency, access, access_reason, until, value, change}`. This branch
  updated the example; the Founder approved the change. Do not edit §7.5.
- **The 8 KB budget (§7.5).** `"currency":"SGD",` adds 17 bytes per listed holding. The two
  largest golden documents are 7,896 bytes (`established`, 14 listed) and 7,908 bytes
  (`two-hundred-holdings`, 16 listed), so they should become about 8,134 and 8,180 bytes and keep
  every holding they list. If a golden account lists fewer holdings than before, that is
  `fitToBudget` working as designed (`packages/core/src/context/compile-context.ts`): keep it,
  and say so in the report.
- The golden files pin the output byte for byte (CONVENTIONS §9, N11). They are written by
  `vitest -u`, never by hand, and their diff is what every agent will read, so it is reviewed.
- A separate branch, `mcp-text-figures`, makes each MCP result's text content the JSON of its
  `structuredContent`, so that Claude, which gives the model only the text, sees the figures.
  This task does not depend on it, but Claude sees the new field only once both are deployed.

## Interface contract

- `financialContextSchema` (`packages/contracts/src/context.ts`): each entry of `holdings` gains
  `currency`, an ISO 4217 code (the file's `currency` schema), required, between `tags` and
  `access`. This is additive (CONVENTIONS §12): no field is renamed or removed.
- `compileContext` fills it from the holding's own `currency` (`HoldingIn.currency`) for every
  listed holding: assets and liabilities, with or without a value. It never comes from the value.
- No other tool, REST route or database change. `list_holdings` and `get_holding` already carry
  `currency`.
