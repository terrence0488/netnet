# P3-T5: The comeback reminder — timing, runs and email

Status: done
Depends on: none
Parallel-safe: yes

## Goal

Someone who has not checked NetNet for 30 days gets one gentle reminder, at
most three per absence and only in their daytime — by push where it is on
(P3-T6's channel), by email otherwise — and every reminder is measurable per
channel.

## Context

- PRD J12 is the contract; architecture §7.10 (Notifications) is the spec:
  `notify()`, `touchChecked`, the reminder run's claim, the 60-a-day email cap,
  the security-email retry sweep.
- This task owns the timing, the runs, `touchChecked`, the `reminder.comeback`
  message and templates, unsubscribe/opened tracking, and the security-email
  retries (which move into the runs; P1 sends the security email straight away
  via `waitUntil`, unchanged).
- P3-T6 owns the `webpush` channel and the endpoint table. This task's send
  logic is: push to every active device in parallel; email only when there is
  none or every push failed. Test the logic with a fake channel; P3-T10
  verifies it end to end.
- Founder item F19: `LINK_SIGNING_SECRET` must be set before the unsubscribe
  and opened links work.
- Backfill decision: the migration creates `reminder_state` for existing users
  with `last_checked_on` = the migration date and `next_due_on` = +30 days, so
  nobody gets a surprise reminder on deploy day; the clock then runs normally.

## Interface contract

- `core.reminder_state(user_id PK, enabled default on, email_enabled default on,
  last_checked_on, next_due_on, sent_since_check, last_sent_at, last_channel,
  last_opened_at)` plus the backfill above. Dates are in the person's
  `time_zone`.
- `touchChecked(userId)` runs after the response (`waitUntil`) on any
  session-authenticated `/api/*` request and any MCP `tools/call` (never
  `tools/list` or the handshake): one `UPDATE … SET last_checked_on = today,
  next_due_on = today + 30, sent_since_check = 0 … AND last_checked_on < today`.
- `GET /api/cron/reminders` (Bearer `$CRON_SECRET`), three Vercel entries at
  **01:00, 09:00, 17:00 UTC** (vercel.json): find due-and-awake rows (`enabled`,
  `sent_since_check < 3`, `next_due_on` on or before local today, local time in
  **08:00–21:00** via `now() AT TIME ZONE profile.time_zone`, somewhere to
  send); claim in one `UPDATE … RETURNING` (`next_due_on` = today + 30,
  `sent_since_check` + 1, `last_sent_at` = now); send through `notify()`; record
  `reminder_sent {channel}` (one per reminder) and `last_channel`; release the
  claim when nothing could be delivered. Reminder emails stop at **60 per UTC
  day**; anyone past that is released for the next daytime run. Each run also
  retries security emails unaccepted for over 10 minutes and under 7 days.
- `notify(userId, {kind: 'reminder.comeback', agentName?})`: the agent named is
  the connected agent used most recently — the guide's name for `claude` /
  `chatgpt`, the registered name for `other` only when ≤ 24 chars of letters,
  digits, spaces, dots or hyphens, else the line is left out. Wording verbatim
  from the PRD: title "NetNet", "Your net worth is due for an update." plus
  "Just ask {agent}." when connected; the email uses that line as subject, one
  **Open NetNet** button to `/app/?r=‹token›`, the footer and one-click
  unsubscribe. Never an amount, total, or holding, type or tag name.
- `POST /api/reminders/unsubscribe {token}` (no session; also the
  `List-Unsubscribe-Post` target) turns email reminders off; the footer's link
  goes through a page that posts once it loads, so a mail scanner changes
  nothing. `POST /api/reminders/opened {token}` (no session) → `204`, fires
  `reminder_opened {channel}` for the first open of each reminder only. Tokens
  are HMAC (`LINK_SIGNING_SECRET`), name person + channel + `last_sent_at`,
  last 60 days, and sign no one in. The web app posts the `?r=` token on open
  and drops it from the address.

      verified addresses only; the 60-a-day cap releases for the next run
