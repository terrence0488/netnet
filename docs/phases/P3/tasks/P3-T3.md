# P3-T3: Settings — currency, country, sign-out

Status: done
Depends on: none
Parallel-safe: yes

## Goal

The person can change their default currency (history re-derived, never
distorted), move country (new types added, nothing removed), and sign out.

## Context

- Architecture §6.6 (changing the default currency), §6.7 (moving country),
  §7.3 (`changeBaseCurrency`, `changeCountry`, `applyPackTypes`), §7.2 (`GET /
  PATCH /api/me`).
- Labels follow the current pack; applied accessibility outcomes and their
  reasons do not move on a country change (§6.7). There is no re-applying
  migration in v1.
- The country and currency lists come from content (`countries.json` via
  `GET /api/content`), never hard-coded (N10). Currency codes are ISO 4217 from
  `packages/contracts`.
- P3-T4 (export/deletion) and P3-T6 (Notifications) extend the Settings screens
  afterwards; this task owns the Settings route and the currency/country/sign-out
  sections. P3-T6 wires push revocation into this task's sign-out flow.

## Interface contract

```ts
changeBaseCurrency(ccy: string): Promise<Write<void>>;
changeCountry(i: { baseCurrency: string; pack: PackRef }): Promise<Write<void>>;
```

- `changeBaseCurrency` re-derives every value's `base_minor` from the stored
  rates at each value's own `fx_rate_date`: one logged, undoable `system`
  change (readable in Activity via P3-T1). Periods stay undistorted (J11).
- `changeCountry`: with no holding yet, the ledger starts over in the new
  currency and types; otherwise the new pack's default types are added and none
  removed. `PATCH /api/me {country, baseCurrency}` drives both; the first
  confirmed country still runs `init` (P1).
- Web Settings screens for currency (every country alphabetically for the
  country step, none pinned — PRD §2.3 rule 2) and sign-out (Better Auth).
  Sign-out keeps its push revocation hook for P3-T6 to wire.
