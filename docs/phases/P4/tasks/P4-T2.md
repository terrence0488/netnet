# P4-T2: The landing page, and `landing_view`

Status: todo
Depends on: none (the screen recording, F21, is made on P4-T1's household)
Parallel-safe: yes

## Goal

`/` becomes the public landing page PRD G-D1 describes: one screen that states the problem in
§2.5's terms, both proofs beneath it, an agent answering a real question from a real balance sheet,
and a call to action straight to sign-up. Each visit fires `landing_view` with a cookie-less
`visitor` hash, so M10 is readable before launch (G-D4).

## Context

- PRD §2.5 and §3.4 G-D1 are the contract. The headline is the widest statement true for all
  three personas: **you can't get useful advice from an AI that doesn't know where you stand.** It
  never opens with "you don't know your net worth" (false and condescending for P-B and P-C).
  Beneath it, two proofs: for someone who has never added it up (P-A: a first picture in minutes,
  the basics or their agent doing the entry, Home saying what they could use, what is locked and
  what they owe) and for someone whose numbers are real but stale and unreadable by their AI (P-B,
  P-C: the agent keeps the picture current from statements, and answers from the real balance
  sheet). P-B and P-C ask where the data lives, whether it is sold and what deletion means before
  signing up (§2.6, A7), so the page answers that too.
- Every claim on the page must be true of the product as built. The facts and where they are
  stated: data in Singapore, encrypted at rest (architecture §4, §8); never sold, no ads, no
  tracking SDKs (§4, §8, CONVENTIONS §14); statements never reach NetNet, the agent reads them and
  sends figures (PRD N2); export any time, deletion erased within 30 days (J10, §8); free, and what
  ships free stays free (§4.2); works with Claude and any agent that supports MCP connectors. Do
  not promise ChatGPT: it joins once OpenAI lists NetNet (J5).
- It is a marketing page with its own design, not a screen in the product (G-D1). It shares
  Poster's brand (`docs/02-prototype/design-system.md`: cream stock, ink outlines, hard offset
  shadows, tomato, the display face) at poster scale, so the page and the app read as one product
  (`decisions.md`, Design). It is built from its own HTML and CSS in `apps/landing`, not from
  the web app's components. No design or scope commentary on the page (design-system §2.1).
- Production stays unannounced until go-live (plan §1 rule 1): the page keeps
  `<meta name="robots" content="noindex">` and gets a `robots.txt` that disallows everything; Stage
  8's checklist removes both. Link previews still need Open Graph tags and an image, because the
  launch note (P4-T10) is posted where links unfurl.
- `landing_view` is in the event schema already (`packages/contracts/src/events.ts`, no props) and
  in architecture §7.7; `analytics.event.visitor` exists and is always null today
  (`apps/api/src/db/analytics.ts`). Architecture §6.4: `visitor` is `sha256(daily_salt ‖ ip ‖
  user-agent)`, truncated, with a salt that changes daily. A salt held only in memory differs
  between function instances and would count one person several times, so each UTC day's salt is a
  random value kept in `core` for that day only and deleted once the day has passed (on the next
  read, and by the daily sweep); a past day's hashes can then never be recomputed. §6.4 is
  rewritten to say so.
- `POST /api/events` accepts `signup_started` without a session, rate-limited per IP; the same
  path and limit serve `landing_view`.

## The screen recording (F21's script)

The Founder records it on a computer, on production or a preview, in an account loaded with P4-T1's
household (`pnpm demo:load`), connected to Claude:

1. Claude's chat, empty. Type: "Can I afford a S$120K car?"
2. Claude calls `get_financial_context` (the tool call visible), then answers from what could be
   used, not from net worth, and notes the stale value and the undecided holding.
3. Follow-up: "How exposed am I to USD?" Claude answers from `exposure`.
4. Cut to NetNet's Home showing the same figures.

No audio. 30–45 seconds. Name, email, avatar and other chats cropped or removed. Exported as MP4
(H.264) and WebM, each under 4 MB, at 1280 px wide, plus a poster frame (PNG). The answer must be
Claude's own, not edited.

## Interface contract

- `apps/landing/index.html` and its CSS: the headline, both proofs, the recording (muted,
  `playsinline`, looping, with controls; no autoplay when the visitor asks for reduced motion,
  where the poster frame shows with a play control), the trust points, "Free", the agents it works
  with, a primary call to action to `/app/signup` and a quiet "Sign in" to `/app/login`. Self-hosted
  fonts and media only (the CSP stays as it is: `default-src 'self'`). Usable without JavaScript
  except for the event.
- `apps/landing/public/robots.txt` (disallow all), Open Graph and Twitter card tags with a 1200×630
  image, a favicon from the app's icon.
- A small script fires `POST /api/events {name: "landing_view", props: {}}` once per page load.
- `POST /api/events`: `landing_view` joins `CLIENT_EVENT_NAMES` and `SESSIONLESS_EVENT_NAMES`; the
  server fills `visitor` for it (and only for it) from the request's IP and user agent and today's
  salt, user id null, segment `unknown`.
- `core.visitor_salt (day date PK, salt bytea)`: today's row made on first use, rows before today
  deleted; read and written only through `apps/api/src/db/`.
- `docs/03-architecture.md` §6.4 (the salt kept only for its day) and §7.7 (`landing_view` marked
  client, sessionless) rewritten in place.
