# P4-T19: Close the two first-confirmation races

Status: todo
Depends on: P4-T13 (the review's L-1 and L-2)
Parallel-safe: yes

## Goal

A first confirmation of `/api/me` creates one ledger, at `data_version` 1, with the first types —
even when two arrive at once — and it can never commit a ledger for an account that is being
deleted.

## Context

- P4-T13's L-1 (`docs/phases/P4/security-review.md`): `apps/api/src/http/me.ts:216-239` reads the
  profile, updates it, then reads the ledger's base currency separately. Two concurrent first
  confirmations can interleave so the second sees `country: null` before the first commits and a
  ledger after it, then calls `changeLedgerCountry` for the same country. A 5-way probe over 400
  people found one anomaly: one ledger with `data_version` 2, the first types deleted and 13
  new ones created. The brief's test passed 60/60 sequentially and 1,000 two-way pairs found none;
  that is why CI sees it rarely. The assertion is legitimate, not a flaky harness.
- P4-T13's L-2: `ledger.ledger_state.user_id` has no key to `core."user"` (the RLS schema test
  deliberately rejects cross-schema keys). `DELETE /api/account` destroys the ledger then deletes
  the user in one transaction; a `PATCH /api/me {country}` already in flight can commit its
  `init` after that transaction, leaving an unreachable ledger outliving the stated 30-day
  window — against J10 and the privacy page. Close it before launch rather than accept it.
- Fixes proposed by the review: L-1 — have `init` report whether it created the ledger
  (`taxonomy.ts` already knows `created`) and skip `changeLedgerCountry` when it did, or decide
  from one value (the `RETURNING` profile's previous country). L-2 — in the deletion transaction
  delete the `core.user` row before `destroy()`, and in `withUser`'s write path take a `FOR SHARE`
  lock on the account row (through a `db/**` helper; `core` belongs there, CONVENTIONS §3) before
  the ledger lock.

## Interface contract

- One first confirmation creates exactly one ledger, one set of types and `data_version` 1; a
  concurrent second confirmation performs no country move.
- A first confirmation racing an account deletion either commits before the deletion and is swept
  by it, or fails; no `ledger` row for an erased id can outlive the deletion.
- No change to the RLS model, the `withUser()` signature's meaning, or the public API shape.
