# P4-T5: The seven remaining launch packs, and the review record

Status: done
Depends on: none
Parallel-safe: yes

## Goal

Draft packs for Indonesia, the Philippines, Thailand, Vietnam, Hong Kong, India and Australia, each
from published sources, ready for a reviewer who knows the market. Make "reviewed before it is
published to production" a check the publish enforces, not a habit.

## Context

- PRD §2.3 is the contract: a pack lists only what differs from the common default; types are
  universal and only labels are local; reasons name the local instrument; "locked until you're
  eligible to withdraw", never an age; where the generic default fixes an answer that is not fixed
  here, the pack asks a fact question instead (Malaysia's EPF is the example); a wrong pack is
  worse than none; packs never restrict. CONVENTIONS §8 adds: every launch pack is reviewed by
  someone who knows the market before it is published to production, and the reviewer is recorded.
- The schema is architecture §7.8 (`Pack`) and its validation rules. `content/packs/sg.json`,
  `my.json` and `gb.json` are the models; `generic.json` is what a pack differs from. Read the
  prototype's `docs/02-prototype/packs.js` notes for how a checklist and its follow-ups read.
- Each pack covers, where the market has them: the mandatory retirement scheme(s) and which parts
  can be withdrawn and when (as facts to ask, never ages); tax-advantaged wrappers; the common
  first-home and investment-property shapes; vehicle loans if common enough to name; housing or
  provident savings schemes; the market's usual bank, brokerage and e-wallet holdings as examples
  (generic names, not brands, unless the brand is the category); and a checklist of what people
  there commonly hold, with follow-ups only after a yes. Currency and locale from
  `content/countries.json`.
- Sources: government and scheme operators' own pages first. Each draft's PR lists, per pack, the
  source for every default, reason and question, with the date read, so the reviewer can check
  quickly. Where a source is unclear, the pack asks rather than decides.
- Drafts must not reach production unreviewed. They live in `content/packs/drafts/`, validated by
  `content:check` like any pack and never published; a pack moves into `content/packs/`, and its
  country gets `pack` in `countries.json`, only in the review's own change (P4-T6).
- The review record: `content/reviews.json` maps each pack key to `{sha256, reviewer, on, notes?}`,
  where `sha256` is the pack document's own hash as `content:publish` computes it. A production
  publish (`--env production`) refuses, whole, any new or changed pack whose hash has no review
  record. Unchanged live documents are not re-published, so SG, MY and GB stay live as they are
  until their own reviews land (P4-T6). The reviewer is named as they agree to be (a name or
  initials), and the commit that records a review carries `Reviewed-by:`.
- The N10 scan (`test/n10/deny-list.json`) must learn the seven markets' scheme and wrapper names,
  so none of them ever slips into code.

## Interface contract

- `content/packs/drafts/{id,ph,th,vn,hk,in,au}.json`, each a valid `Pack` with `id` equal to its
  file name.
- `content/reviews.json` with a schema in `packages/contracts` (`reviewsSchema`), validated by
  `content:check` (every key names a pack in `content/packs/`, hashes are 64 hex characters).
- `scripts/content-publish.ts`: in production, a new or changed `pack` document without a matching
  review record fails the publish with a message naming the pack and saying a review is needed;
  local and preview publish as today. `content/packs/drafts/` is never published.
- `test/n10/deny-list.json`: the new terms, each a whole word as the scan matches.

Deviations:
- The guard lives in `publishContent` (`apps/api/src/content/publish.ts`, not in the brief's
  file list) as an optional `admit` hook, with the script passing it in production. Only inside
  the publish's transaction, under the content lock, is it known which documents are new or
  changed; a check in the script before the transaction could pass a document that a concurrent
  publish changed in between. No §7 interface changes.
- The guard applies to every pack, `generic` included, as the brief's "any new or changed pack"
  reads. Unchanged live packs (generic, SG, MY, GB) pass, so today's production publish is
  unaffected.
- Sources were read through web search restricted to each operator's own domain: this
  environment's network policy refused direct fetches of the government hosts. The PR's sources
  list says so and asks the reviewer to open each link.
