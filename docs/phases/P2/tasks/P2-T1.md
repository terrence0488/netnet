# P2-T1: Google and Apple sign-in

Status: done
Depends on: none
Parallel-safe: yes

## Goal

A visitor signs up or signs in with Google or Apple, verified, through the providers'
official buttons; the sign-up events carry which way in was chosen.

## Context

P1-T11 built email + password through Better Auth (architecture §4 Stack, "Accounts"; §8 "Auth
and security"). This task adds the two providers to the same Better Auth config and the same
sign-up / sign-in screens. PRD: J1 (sign-up asks for nothing else; provider sign-ups are already
verified), §3.5 (`method` on `signup_started` / `account_created`).

Requires the Founder's setup first: F17 (Google OAuth client) and F18 (Apple Services ID, domain
verification, key; needs F1's Apple Developer enrolment). The secrets go straight into Vercel env
and are never in chat or a file (plan §5).

## Interface contract

- Better Auth providers Google and Apple on the existing `/api/auth/*` paths (architecture §7.1
  URL map). No new paths; sessions, cookies and the Origin check unchanged (§8).
- `signup_started {method}` and `account_created {method}` with `method: google | apple`
  (architecture §7.7; PRD §3.5). Extend the event schemas in `packages/contracts` if P1's enums
  lack them.
- Provider accounts have `email_verified` true and skip verification; the email flow is untouched.
- New env vars: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `APPLE_CLIENT_ID`, `APPLE_TEAM_ID`,
  `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY`. Names only in `.env.example` (CONVENTIONS §7).

## Files in scope

- `apps/api/src/auth/**` (provider config)
- `apps/web/src/routes/**` (sign-up and sign-in screens only), shared button components they use
- `packages/contracts/**` (event schemas, only if `method` needs extending)
- `.env.example` (names only)
- Integration and E2E tests for this task

## Done criteria

- [x] Sign-up and sign-in with Google and with Apple each create or resume one account, verified,
      asking for nothing else; the official sign-in buttons are used for both (architecture §8)
- [x] `signup_started` / `account_created` fire with `method: google | apple`; the email flow and
      its events are unchanged
- [x] Tests written and passing: integration tests with Google and Apple faked at the OAuth
      interface (account created, verified, `method` carried, returning sign-in resumes);
      Playwright checks the official buttons render and start the flow
- [x] Follows CONVENTIONS.md
