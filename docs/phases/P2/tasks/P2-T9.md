## Goal

The Add form and the holding value sheet match the prototype and the design system:
Tags on Add, a currency symbol on amounts, aligned fields, nothing overflowing.

## Context

Second production review (`docs/phases/P2/feedback.md` #6, #9). Prototype references:
`renderAdd` (`docs/02-prototype/app.js:1891`) — Currency + Value in a `.two` row, As-of
date below, Tags chips (line 1924); `sheetValue` (app.js:2114) — Asset/Liability Value +
Currency in a `.two` row, As-of below. Visual spec: design-system §6 **Amount entry**
(display-size number, currency symbol in `ink-3`) and **Fields** (boxed, equal). P2-T6
put tag chips on the Add form, so their absence in production is a regression. The
production theme (design-b) stays; only the drift is fixed.

`e2e/holding.spec.ts`, `e2e/taxonomy.spec.ts` (extended as briefed).
Tests run / results: focused specs green on phone (390) and computer (1280):
`add` + `taxonomy` 40 passed, `holding` 36 passed, incl. the pre-existing POST/PATCH
`tagIds` assertions. Unit 1250 green (`pnpm test`, N10 scan incl.), `pnpm lint` and
`pnpm typecheck` green. Full E2E against a local CI-equivalent stack (Postgres 18,
migrated + seeded, provider flags): 274 passed, 4 skipped; 6 agent/basics failures were
the spec helpers' `DATABASE_URL` privilege (app role cannot read `analytics.event`) and
all 6 pass with CI's owner URL.
Deviations: (1) The Tags row now always shows on Add, overturning P2-T6's tested
hide-when-empty: reproduction proved chips render whenever tags exist and the API serves
them, so "missing in production" is the empty state, and the prototype shows Tags always.
The `hides tags` test now asserts the row with its empty state. (2) The date input stands
2px taller than text/select in Chromium (its native segments); equalising that would need
per-UA compensation with unverifiable Safari effects, so the test pins pair and stacked
heights exact and covers the date for overflow instead. The currency symbol and the date
overflow were not reproducible in Chromium (both correct at 390/320/1280) and are now
locked by tests; an iOS Safari look remains a Stage 6 manual check.
Open issues: following "Add tags" mid-form loses untyped input (form state is not kept
across the navigation). The "TAGS" label in the holding Tags sheet keeps its own style
(out of scope: value sheet only).
