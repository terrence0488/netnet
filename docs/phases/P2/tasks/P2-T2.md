# P2-T2: Onboarding basics and the agent route

Status: todo
Depends on: P2-T6 (mechanical ordering only: both tasks extend `POST /api/holdings`; this
task's feature needs nothing from T6)
Parallel-safe: yes

## Goal

Onboarding's "Let's start…" screen offers the basics or the agent as the second route. The
basics walk the pack's checklist one question per screen and save every answer at once; the
agent route ends on a blank Home with no waiting state.

## Context

P1-T14 built sign-up/in plus the country and segment screens; returning users resume through
`profile.onboarding_state` (architecture §6.2). The basics' questions are the pack `checklist`
(architecture §7.8 Content schemas); follow-ups ride `onlyIf`. PRD: J1 (the start screen, the
basics, Skip, Back, "Done for now", the agent route, the blank Home, the P-A walk-through).

Seams: `tagIds` on `POST /api/holdings` belongs to P2-T6 (wave 1); this task adds `via` beside
it. The blank-Home prompt UI is P2-T4's empty-Home component; this task ends the route at Home
and wires the onboarding connect entry.

## Interface contract

- `POST /api/holdings` takes `via: "guided" | "form"` (architecture §7.2); `holding_created
  {source: web, via: guided}` fires for basics answers (architecture §7.7).
- Yes-to-no on Back removes what the yes added plus anything asked only because of it, through
  `DELETE /api/holdings/:id` (exists, P1); the removals write audit rows like any delete.
- `POST /api/agent/attempts {client, entry: "onboarding", platform}` and the existing connect
  flow (P1-T13/T17); `agent_connection_started {entry: onboarding}` fires.

## Files in scope

- `apps/web/src/routes/**` (onboarding screens and the start screen only)
- `apps/api/src/http/**` (the holdings route's `via` only) and the `holding_created` wiring
- `content/packs/*.json` (only if a launch pack lacks its checklist; a new version through the
  publish flow, never an edit in place — CONVENTIONS §8)
- E2E and integration tests for this task
