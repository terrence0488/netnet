# P1-T4: Database — schemas, roles, row-level security and withUser
Status: todo
Depends on: P1-T1
Parallel-safe: yes

## Goal
The three Postgres schemas and four roles exist as drizzle-kit migrations. Every `ledger` table is
walled off per user by `FORCE` row-level security and composite keys, `withUser()` is the only way
in, CI proves both, and each pull request gets its own Neon branch.

## Context
- Read: architecture §6.1–6.4 (roles and tables), §6.8 (the write transaction), §7.3 (`withUser`),
  §8 (the Isolation row), §9.1–9.2. CONVENTIONS §3, §9 (the Row-level security and Ledger rows),
  §10.
- **Tables in this task:** everything in §6.2–6.4 that P1 uses: `profile`, `agent_connection`,
  `connection_attempt`, `content_doc`, `content_current`, `content_audit`, `fx_rate`, `rate_limit`,
  every `ledger` table in §6.3, and `analytics.event`. Not `notification_endpoint` or
  `reminder_state` (P3). Better Auth's and its OAuth plugin's tables are generated by P1-T11 and
  P1-T13, in `core`.
- **Neon roles.** Roles made in Neon's console or API inherit `neon_superuser`, which bypasses RLS.
  `netnet_owner` is made in the console (F7). `netnet_app`, `netnet_metrics` and
  `netnet_content_admin` are made **by SQL** (`CREATE ROLE … NOBYPASSRLS`), in an idempotent
  bootstrap run as `netnet_owner`, which sets `netnet_app`'s password from a secret at run time
  (`NETNET_APP_DB_PASSWORD_*`, F7). No password ever appears in a migration or in the repo. P1-T2
  confirms the Neon behaviour.
- `app.user_id` is set with `set_config('app.user_id', $1, true)`: transaction-local, safe with
  Neon's pooler.
- **Previews.** When a pull request opens or updates, CI creates (or reuses) a branch of
  `netnet-preview` named after it, runs the bootstrap and migrations as owner, seeds fictional data,
  and hands the branch's pooled `netnet_app` connection string to that PR's Vercel preview deploy.
  When the pull request closes, CI deletes the branch. At most 10 branches (§9.1).
- **Tests run on real Postgres:** CI's `postgres:17` service; in a session, the preinstalled Postgres
  16 (or Docker). PGlite only if the RLS suite passes on it unchanged.
- An injectable clock (`now()`) is part of the transaction context, so later tasks can test time
  rules (batches, rate limits) with a fake clock.

## Interface contract
```ts
// apps/api/src/ledger/with-user.ts — signature from architecture §7.3
type Actor = { kind: 'user' | 'agent' | 'system'; connectionId?: string; clientName?: string };
function withUser<T>(userId: string, actor: Actor, fn: (tx: LedgerTx) => Promise<T>,
                     opts?: { write?: boolean }): Promise<T>;
```
- Here `LedgerTx` is the Drizzle transaction plus `actor` and `now`; P1-T10 builds the `Ledger`
  interface on it.
- `withUser` opens a transaction, sets `app.user_id`, and for `write` takes
  `SELECT … FROM ledger.ledger_state WHERE user_id = $1 FOR UPDATE`. For an `agent` actor it checks
  `core.agent_connection` (`id = connectionId`, `user_id = userId`, `revoked_at IS NULL`) and throws
  a typed `ConnectionRevoked` error otherwise (P1-T15 maps it to `401 invalid_token`).
- `apps/api/src/lib/ids.ts`: `newId(prefix)` → prefixed ULID (`usr_`, `hld_`, `val_`, `typ_`, `tag_`,
  `aud_`, `bat_`, `con_`, `att_`).
- Environment: `DATABASE_URL` (the app, pooled); `DATABASE_OWNER_URL` (CI migrations only).
- Scripts: `pnpm db:bootstrap`, `pnpm db:migrate`, `pnpm db:seed` (fictional data only).
- Report the exact form of the production `DATABASE_URL` for the Founder (F12), without the password.

## Done criteria
- [ ] Every table in scope exists with the columns in §6.2–6.4: prefixed ULID ids, money as `bigint`,
      value dates as `date`, instants as `timestamptz`.
- [ ] Every `ledger` table has `user_id` in its primary key, composite foreign keys, `ENABLE` and
      `FORCE ROW LEVEL SECURITY` and the one policy. A schema test reads the catalog, so it also
      covers any table added later, and fails the build if one lacks any of these.
- [ ] Grants per §6.1: `netnet_app` reads and writes `core`, reaches `ledger` only through RLS, and
      can only insert into `analytics.event`; `netnet_metrics` reads `analytics` only;
      `netnet_content_admin` writes `core.content_*` only. A test asserts `netnet_app` has
      `rolbypassrls = false`, owns nothing, and is a member of no role that bypasses RLS.
- [ ] RLS suite, as `netnet_app`: with user B set, a raw `SELECT *` on every `ledger` table returns
      none of A's rows; with no user set, nothing; inserting a row with A's `user_id` while B is set
      fails; a composite foreign key cannot point at another user's row.
- [ ] `withUser`: the user is set for the transaction only (the next query on the same pooled
      connection sees nothing); the write lock serialises two concurrent writes for one user and not
      for two users; a revoked agent connection is rejected.
- [ ] Migrations apply to an empty database in CI. A pull request's Neon branch is created, migrated,
      seeded, wired into its preview, and deleted when it closes.
- [ ] Follows CONVENTIONS.md
