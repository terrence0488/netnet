# P1-T8: Content store and exchange rates
Status: todo
Depends on: P1-T3, P1-T4
Parallel-safe: yes

## Goal
Published content lives in the database as immutable versions that the running system reads, and
exchange rates are fetched daily into `core.fx_rate` with their history, so a value written in any
supported currency gets its rate at write time.

## Context
- Read: PRD §2.3 (packs: a published schema; versioned; audited and reversible; no access to user
  data). Architecture §6.2 (`content_*`, `fx_rate`), §6.5 (publishing and reading), §6.6 (money and
  exchange rates), §7.2 (the content routes), §9.3 (the FX cron at 17:00 UTC), §10 (the FX row).
  CONVENTIONS §7, §8.
- **Publishing** is per environment: `pnpm content:publish --env preview|production`. CI publishes to
  each preview after its migrations; the production workflow (P1-T18) publishes to production with
  `--strict`. The author is the git author; `source_commit` is the commit.
- **Rates.** ECB via Frankfurter (free, no key, history to 1999). **Choose the fallback source** for
  currencies the ECB lacks (VND, TWD, AED, …): free, no key, daily history, stable. Record the choice
  and the reason in `docs/decisions.md` (Architecture). Every currency in `content/countries.json`
  is covered by one of the two, or is listed as unsupported (→ `CURRENCY_UNSUPPORTED`).
- Rates are stored as `per_usd`; cross rates go through USD. A lookup takes the latest rate on or
  before the value's date; before the fallback's history begins, the nearest later rate, with its
  date (architecture §6.6).
- A one-off backfill (`pnpm fx:backfill --from 2000-01-01 --env <env>`) per environment; the daily
  cron fills the new day and any gap.
- Crons check `Authorization: Bearer $CRON_SECRET` (F9). Vercel Cron calls with `GET`.
- A failed fetch keeps the last rate in use and logs an error (the Founder alert is P4's).

## Interface contract
- `apps/api/src/content/store.ts`: `getCurrent(kind, key) → {version, body}` (cached 60 s),
  `getVersion(kind, key, version)` (cached indefinitely), `getPackChain(country) → Pack[]` (built with
  `core.packChain`).
- REST: `GET /api/content/current` → `{[kind]: {[key]: version}}`; `GET
  /api/content/:kind/:key@:version` → the document, `Cache-Control: public, max-age=31536000,
  immutable`. These hold no user data and need no session.
- `scripts/content-publish.ts`: validates every document (`validateContent`, P1-T3). Any error
  rejects the whole publish. Otherwise, in one transaction: a new `content_doc` row only for a
  changed body (by `sha256`), `content_current` moved, `content_audit` written. `--rollback
  kind/key@version` points `content_current` back, audited.
- `apps/api/src/content/fx.ts`: `crossRate(from, to, date) → Promise<{rate: string; rateDate: string;
  source: 'ecb' | 'fallback'}>`, where `rate` is a decimal string in major units (1 `from` = `rate`
  `to`), the form a statement shows. The Ledger (P1-T10) converts minor units with `core.convert`,
  adjusting for the two currencies' exponents.
- `GET /api/cron/fx`, and its `vercel.json` cron entry at `0 17 * * *`.

Deviations:
- The queries live in `apps/api/src/db/` (outside the listed files): only `db/**` may touch `core`
  (CONVENTIONS §3). `jobs/cron.ts` is shared by every cron route.
- The country list's key is `countries` (`countries/countries@1`); packs and guides are keyed by id.
  `getVersion` returns `{version, body}`, as `getCurrent` does; both throw `NOT_FOUND`.
- A changed body that equals an earlier version reuses that version instead of writing a copy.
  Rollback also checks that the live set with the older version still validates.
- `content:publish` and `fx:backfill` read `DATABASE_URL` (`netnet_app`, as `db:seed` does); `--env
  local|preview|production` is a required interlock, not a connection selector. A production
  publish requires `--strict`. The author is HEAD's git author name; a rollback's actor is
  `git config user.name`, else that author.
- A missing or wrong bearer is `401` with `WWW-Authenticate: Bearer` through the error handler's
  existing passthrough: §7.5 has no code for it.
- ECB rates are read through Frankfurter's v2 API (`providers=ECB`, as published against EUR); v1
  now sends deprecation headers. Rates derived by division keep 12 significant digits, rounded half
  away from zero.
- `crossRate`: `rateDate` is the older leg's date, or the later one when a leg is after the value's
  date; `source` is `fallback` if either leg is. X → X is `1`. A malformed code is
  `CURRENCY_UNSUPPORTED`, a non-calendar date `VALIDATION_FAILED`. `nearest` lists codes one edit
  away (a swap counts as one), else two, at most five.
- The cron fetches each source from a week back (late publications), or from its newest rate if
  older, with one retry. A stored rate is never replaced. A failed run answers 502 and logs
  `fx_<source>_fetch_failed` with the source's HTTP status (502 if it never answered).
- Each currency has one source, from static lists in `fx-sources.ts`: ECB 29 (with EUR), fallback
  117, unsupported 5 (SOS, SSP, XCG, XPF, ZWG). The ECB's rows for currencies it no longer
  publishes are dropped; RUB comes from the fallback across its history.
