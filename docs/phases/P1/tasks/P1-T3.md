# P1-T3: Content — schemas, starting packs, countries and agent guides
Status: todo
Depends on: P1-T1
Parallel-safe: yes

## Goal
The jurisdiction packs, the country list and the agent setup guides exist as validated JSON in
`content/`, with their zod schemas in `packages/contracts`, and `pnpm content:check` enforces every
rule in architecture §7.8.

## Context
- Read: PRD §2.3 (rules 1–4 and the four constraints), J2 (fact questions, stated reasons, the
  consequence), J5 (guides, "Other agent", Grok and Muse parked). Architecture §6.5, §6.7, §7.8.
  CONVENTIONS §8.
- **Port, don't reinvent:** `docs/02-prototype/packs.js` (universal types; the generic, SG, MY and
  UK packs), `docs/02-prototype/connectors.js` (Claude, ChatGPT and Other; Grok and Muse stay out of
  `content/`), `docs/02-prototype/agents/*.svg` (logos → `content/images/agents/`),
  `docs/02-prototype/connect/README.md` (screenshot names → `content/images/connect/`).
- The universal type list in §7.8 is the contract. Where `packs.js` differs, §7.8 wins; list each
  difference in the report.
- Keys: packs by lowercase ISO code (`generic`, `sg`, `my`, `gb`). `countries.json` is keyed by ISO
  3166-1 alpha-2 plus `XK`, every country, each with its ISO 4217 currency and a `pack` only where one
  exists. Country names are not content: the web app takes them from `Intl.DisplayNames`.
- Copy: ask facts, not categories; show the consequence; "locked until you're eligible to
  withdraw", never an age. Generic's `meaning` text is universal and names no local scheme.
- Screenshots are not in the repo yet (F11). Guides reference their paths. `content:check` passes
  with a missing image; `content:check --strict` (used for a production publish) fails on one.
- `matchHosts`: use the hosts the spike (P1-T2) observed, if its report exists. Otherwise
  `claude.ai`, `claude.com` and `anthropic.com` for Claude; `chatgpt.com` and `openai.com` for
  ChatGPT; and note it for P1-T13 to confirm.

## Interface contract
- `packages/contracts/src/content.ts`: `Universal`, `Access`, `Outcome`, `Pack`, `Countries` and
  `AgentGuide` exactly as architecture §7.8, as zod schemas with inferred types.
- `validateContent(docs) → {ok: true} | {ok: false, errors: {doc, path, message}[]}`, implementing
  every rule under §7.8 "Validation", and returning every error, not the first.
- `pnpm content:check [--strict]` validates all of `content/` and exits non-zero on any error.

## Files in scope
`content/**`, `packages/contracts/src/content.ts` and its tests, `scripts/content-check.ts`, the
root `package.json` script.

Deviations:
- `packs.js` against §7.8 (§7.8 followed in each case):
  - `UNIVERSAL_TYPES` carries each type's `side` (asset, liability, any); §7.8's `Universal` is a
    bare union, so the side is not content.
  - `packs.js` has no `meaning` or `cadenceDays`. The generic pack now defines both for every type:
    meaning written for an agent, naming no local scheme; cadences from the prototype's
    `data.js` (30 days for cash, listed, crypto and card; 90 for retirement, equity, wrapper,
    mortgage, loan and other; 180 for a vehicle; 365 for property).
  - `packs.js` leaves out sections a pack does not change (SG and GB have no `questions`); §7.8
    makes every section required, so each pack has all of them, empty where it adds nothing.
  - `COUNTRY_CCY` and `COUNTRY_PACK` merge into `countries.json`. `REGION_NAMES` (the HK and MO
    name overrides) is dropped: names are not content.
  - Antarctica (AQ) stays out, as in `packs.js`: it is not a country and has no currency. The list
    is the other 248 ISO 3166-1 codes plus XK.
  - Checklist keys are in §7.8's order; the values are unchanged.
- `connectors.js` against §7.8:
  - A step's `url: true` (show the connector address in that step) has no field in §7.8. The
    step now reads "paste NetNet’s connector address" and the flow shows the address with Copy
    (P1-T17). If the address must sit inside one step, §7.8 needs a field: raised, not improvised.
  - `deepLink` becomes `prefillUrl` with the `{prompt}` slot.
  - Other's `name` ("Your agent") and `label` ("Other agent") become one `name`, "Other agent";
    `generic: true` becomes the id `other`. `parked` becomes absence (Grok and Muse are not in
    `content/`).
  - One `order` replaces both the list order (Claude, ChatGPT, Other) and `ROLL` (the button's
    ChatGPT, Claude); the list order is used.
  - `plans` is left out: which plans allow a connector is parked (PRD §9).
- Image paths are relative to `content/` (`images/connect/claude-phone-1.png`), served under
  `/content/*` (§7.1).
- `validateContent(docs)` takes `{kind, doc, body}[]`, where `doc` names the document in errors
  (content:check passes its path under `content/`). Packs and guides are identified by their
  `id`; content:check requires each file to be named after it, so content:publish's key is the id.
- Rules beyond §7.8's list, each so that every reference resolves: one country list; a country's
  `pack` exists; checklist ids and pack type keys are unique within a pack; a checklist item's `u`
  is its type's; a checklist `answer` is an answer to its universal's question (the pack's, else
  generic's); guide ids are unique; `not_sure` is reserved as an answer id (§7.4); a question has
  at least two answers; unknown keys are rejected; formats for ids, codes, locales, ISO 4217
  currencies in circulation, image paths, hosts and `prefillUrl`. A document that fails its schema
  reports its shape errors and is left out of the relational rules.
