# P1-T9: Core — compileContext, the agent's context
Status: todo
Depends on: P1-T6
Parallel-safe: yes

## Goal
`core.compileContext()` turns a user's ledger data into architecture §7.5's document: the four
context layers, ordered by importance, at most 8 KB, byte-identical for identical input. This is the
differentiator (PRD §2.4), and its golden files are its contract.

## Context
- Read: PRD §2.4 (the four layers; dense, not comprehensive; facts and structure, never judgement),
  J8 (every criterion), N11. Architecture §7.5 (shape, 8 KB, order, holdings largest first capped at
  25, the rest summarised by type with a pointer to `list_holdings`), §6.7 (labels follow the current
  pack; outcomes and reasons stay as applied), §8 (the Prompt injection and Untrusted agent names
  rows). CONVENTIONS §9 (golden files).
- `meaning` is the chain's `meaning[universal]`, pack text, never hard-coded. `answer_guide` is fixed
  text in core: it is an opinion about the interaction, universal, not local knowledge.
- `written_by` is `web`, `system`, or `agent:<name>`, where `<name>` is the guide name for a
  connection classified `claude` or `chatgpt`, and `other` for anything else. An agent's registered
  name is untrusted text (§8) and never reaches another agent's context.
- `picture.freshness` is one of `empty`, `fresh`, `some_stale`, `mostly_stale` (more than half
  stale). `picture.notes` are at most five fixed English templates, filled with numbers and holding
  names only, most important first. Undecided holdings always produce a note: an affordability
  answer must be qualified (J2).
- **Size budget.** Past 8 KB, drop in this order until it fits: holdings beyond the cap, concentration
  entries beyond five, notes beyond three. Test with a 200-holding account.
- Amounts are JSON numbers in major units, rendered from minor units by `fromMinor`. Keys appear in
  §7.5's order. Nothing depends on object insertion accidents: sorting is explicit, with ties broken
  by id.

## Interface contract
```ts
compileContext(data: ContextInput, chain: Pack[], today: string,
               opts: { baseline?: Baseline }): FinancialContext
```
- `ContextInput` = `{baseCurrency, holdings, values, types, tags, connections: {id, client,
  guideName?}[]}`, which `Ledger.context()` returns (P1-T10).
- `FinancialContext` is §7.5's shape as a zod schema in `packages/contracts/src/context.ts`; it is
  `get_financial_context`'s `outputSchema` (P1-T15).

## Files in scope
`packages/core/src/context/**`, `packages/contracts/src/context.ts`, golden files and tests.

## Done criteria
- [ ] The output matches §7.5's shape and key order, and validates against the schema.
- [ ] Golden files, byte-identical on every run, for at least: an empty account; a P-A account (three
      holdings, one undecided, one liability); a P-C account (30 holdings, four currencies, stale
      values, archived holdings); a 200-holding account (the cap and `omitted`); a holder in one
      country with holdings from two others.
- [ ] Every fixture is at most 8 KB; a property test over random fictional accounts holds the cap.
- [ ] Facts, never advice: a test scans every template and the `answer_guide` for advice wording
      ("should", "recommend", "consider", "avoid", "don't").
- [ ] Undecided never counts in `could_use` and is always reported (`picture.undecided` and a note).
- [ ] No `Date`, no randomness, no I/O.
- [ ] Follows CONVENTIONS.md
