# P1-T14: Web — sign-up, sign-in and onboarding screens
Status: todo
Depends on: P1-T5, P1-T7, P1-T11
Parallel-safe: yes

## Goal
A visitor signs up with an email and a password, signs in, resets a password, and goes through P1's
onboarding: where they live (inferred, confirmed with one tap, or any country from an alphabetical
list), then the optional segment, landing on Home. A returning user resumes onboarding or goes
straight to Home.

## Context
- Read: PRD J1 (sign-up asks nothing else; verification never blocks; a returning user resumes;
  one skippable segment question; events), J2 (the country confirmed by one question; every country
  listed alphabetically with none pinned; the currency default), §2.3 rule 2. Design-system §2.1, §6,
  §7 (chrome-less routes). CONVENTIONS §13.
- **Prototype reference:** the sign-up, log-in and onboarding screens in `docs/02-prototype/app.js`,
  and its `auth` and `geo` tests.
- **P1's onboarding ends at Home after the segment.** P2 inserts the "Let's start…" screen and the
  basics after it, so build onboarding as a list of steps, where that is an insertion.
- **Country list:** the keys of `countries.json` (from the content API), names from
  `Intl.DisplayNames` in the user's language, sorted with `Intl.Collator`, none pinned. The default
  comes from `GET /api/geo`.
- **Unverified:** a quiet line with Resend. Verification blocks nothing here (the agent is P1-T17's).
- **Time zone:** sent at sign-up, and by `PATCH /api/me` whenever the browser's differs from the
  profile's.
- **Events:** `signup_started {method: email}` before the account exists; `session_started` from
  P1-T7's session tracker, mounted in the shell.

## Interface contract
Consumes `/api/auth/*`, `GET/PATCH /api/me`, `GET /api/geo` (P1-T11) and `GET /api/content/*`
(P1-T8). Routes: `/app/signup`, `/app/login`, `/app/forgot`, `/app/reset`, `/app/verify`,
`/app/onboarding/*`.

## Files in scope
`apps/web/src/routes/{signup,login,forgot,reset,verify,onboarding}/**`, `apps/web/src/app/` (route
guards: signed out → log-in; onboarding unfinished → resume), `e2e/auth.spec.ts`,
`e2e/onboarding.spec.ts`.

## Done criteria
- [ ] Sign-up, sign-in, sign-out, forgot and reset password, the verify link's landing page, and
      resend.
- [ ] Onboarding: one question per screen; the inferred country confirmed with one tap or changed
      from the alphabetical list; the segment skippable; Back works; a returning user resumes.
- [ ] Errors in plain language with a next step (a wrong password, an address already registered,
      no network); reset never says whether an account exists.
- [ ] Playwright: every flow at 390 and 1280 px; no horizontal scroll at 320 px; axe on every screen;
      the events asserted.
- [ ] Follows CONVENTIONS.md

Deviations:
- The two API constants (the manager's decision); their tests updated.
- Outside the listed files: `api/{auth,account,content}.ts`; the components above (Choice is a
  design-system component P1-T16 also needs); `routes/account/` and the Account tab, since sign-out
  needs a place on a phone and a computer (the prototype's Account tab; P3's settings join it);
  `routes/gallery/`; the shared E2E support, the shell, smoke and gallery specs (the screens with
  chrome now need a session) and `playwright.config.ts`.
- Sign-up is the prototype's two steps (email, then `/signup/password`): `signup_started` fires on
  the email step, before the account exists, also for an address that turns out to have one (only
  the create call can tell). A 422 then goes to log-in, email filled, "You already have an account.
  Log in instead."
- Signed out → log-in, as the brief says; the prototype sends a browser that never had an account
  to sign-up. Forgot password is its own route (`/forgot`), as the brief says; the prototype does it
  inline on log-in.
- The country suggestion is `GET /api/geo`, then a region the browser's language states (`en-MY` →
  MY), PRD §2.3 rule 2's locale fallback; the brief names only geo. The suggestion is not repeated
  in "Somewhere else"'s list (the prototype's behaviour); with none, the list is every country.
- **Stop-and-raise, not built:** the totals currency is shown ("Totals in SGD") but not
  changeable at onboarding, unlike the prototype's Change and PRD J2's "changeable": `PATCH
  /api/me` takes no currency (§7.2), P1-T12 sets the base currency from the first country, and the
  plan puts changing it in P3's settings. Adding it here is a §7 change for the Founder.
- Log out reloads the page at `/app/login`, so nothing of the account stays in memory; the
  prototype's remembered email on the log-in screen is therefore not kept.
- The session is `GET /api/me` (401 → signed out), not Better Auth's `get-session`, whose body
  carries the session token; a signed-out page therefore logs one expected 401.
- The account specs skip when `E2E_BASE_URL` is set: a deployment counts sign-ups per real IP
  (5 a minute) and its database, which holds the reset tokens, is out of reach. Locally each test
  has its own `x-forwarded-for`.
