# P1-T7: Analytics — track(), the event schemas and the client events endpoint
Status: todo
Depends on: P1-T4
Parallel-safe: yes

## Goal
Every §3.5 event exists as a strict schema, and `track()` is the only way to write one, attaching
`segment`, `user_id` and `app_version` itself. The web app sends its client-side events through
`POST /api/events`. The privacy tests make a leak a failing build.

## Context
- Read: PRD §3.5 (the events, `segment`, the privacy constraint) and N9. Architecture §6.4, §7.7
  (props, who emits each, client vs server). CONVENTIONS §6, §9 (the Privacy row).
- **All 21 events are defined now.** The schema is the contract, even for events first fired in a
  later phase.
- Server events are written after the response (`waitUntil` on Vercel; awaited directly in tests).
- `segment` comes from `core.profile` (or the request context when it is already loaded), and is
  `unknown` until onboarding sets it.
- Client events accepted by `POST /api/events` are only those §7.7 marks *client*: `signup_started`,
  `session_started`, `agent_connection_started`, `insights_viewed`, `push_prompt_shown`,
  `push_prompt_result` (and `landing_view` in P4). Without a session, only `signup_started` is
  accepted. The endpoint is rate-limited per IP.
- The `visitor` hash is P4's (with the landing page); the column stays nullable.

## Interface contract
- `packages/contracts/src/events.ts`: `EventName`; `eventSchemas: Record<EventName, ZodObject>`, each
  `.strict()`, every prop an enum, a boolean or a bounded integer, named exactly as §3.5 and §7.7.
- `apps/api/src/events/track.ts`: `track(name, props, ctx: {userId?: string; segment?: Segment;
  appVersion: string})`. An unknown name or prop throws outside production and is logged and dropped
  in production.
- `POST /api/events {name, props}` → `204`; an unknown or server-only name → `400
  VALIDATION_FAILED`.
- `apps/web/src/api/events.ts`: `trackClient(name, props)` and a session tracker that fires
  `session_started` on the first activity after 30 minutes idle (P1-T14 mounts it).

## Files in scope
`packages/contracts/src/events.ts`, `apps/api/src/events/**`, `apps/api/src/http/events.ts`,
`apps/web/src/api/events.ts`, their tests.

## Done criteria
- [ ] The schemas match §7.7 exactly: names, props, enums, snake_case.
- [ ] Privacy tests: no schema has a free-text string prop (enums only); no prop name suggests an
      amount or a name (`amount`, `value`, `total`, `balance`, `name`, …); `track()` rejects extra
      props.
- [ ] `netnet_app` can insert into `analytics.event` and cannot select from it.
- [ ] `session_started` fires after 30 minutes idle and not before (fake clock).
- [ ] `POST /api/events`: accepted client events, rejected server-only events, rejected unknown
      props, the unauthenticated rule, the rate limit.
- [ ] Follows CONVENTIONS.md
