# P1-T13: Agent OAuth server and connections
Status: done
Depends on: P1-T2 (verdict), P1-T3, P1-T8, P1-T11
Parallel-safe: yes

## Goal
Any standard MCP agent connects to NetNet by OAuth 2.1, with no token to paste: discovery metadata,
CIMD and DCR registration, authorization code with PKCE, the approval page's API, JWT access tokens
and rotating refresh tokens. Each approval creates a classified connection, moves on the attempt the
web app is polling, and sends the security email. Connections can be listed and revoked.

## Context
- Read: PRD J5 (every criterion but the prompt handoff). Architecture §3 (classification by
  `matchHosts`), §5.1 (the sequence), §6.2 (`agent_connection`, `connection_attempt`, the OAuth
  tables), §7.1, §7.2 (`/api/agent/*`), §7.6 (all), §7.7 (the `agent_connection_*` events, failed
  steps and timeouts), §7.10 (the security email), §8 (Agent access, Rate limits, Untrusted agent
  names). The spike's verdict (`docs/phases/P1/spike.md`) sets the library and its settings.
- **The approval page's UI is P1-T17's.** This task provides its API: read the pending request (the
  registered name, `registration`, whether the name is verified, the scopes), then Allow or Cancel.
  Use the consent endpoints the chosen library provides; if it has none, add `GET` and `POST
  /api/agent/approval` and record them in architecture §7.2 (plan §1 rule 4). The page is
  `/app/connect/approve`, served with `frame-ancestors 'none'`.
- **Verified users only:** approving with an unverified email returns `EMAIL_NOT_VERIFIED`.
- **From the spike** (`docs/phases/P1/spike.md` §5): every new connection shows the approval page,
  so turn off remembered consent; turn the library's JSON `{redirect, url}` answer to a browser's
  `GET` into a `302`, keeping its cookies; and drive the connect flow in a real browser in E2E, not
  only a scripted client. Claude connects by CIMD as `https://claude.ai/oauth/mcp-oauth-client-metadata`
  and returns to `claude.ai`; OpenAI's Codex as `https://chatgpt.com/oauth/codex/client.json`.
- **Classification:** the CIMD client id's host, or a DCR client's redirect URI host, against the
  named guides' `matchHosts`, unlisted ones included (so OpenAI's Codex, at `chatgpt.com`, is
  `chatgpt`); anything else is `other`. Confirm the hosts against the spike's
  findings and fix `content/agents/*.json` if they differ.
- **Attempts:** `started` → `approved` (Allow) → `live` (the first successful tool call, marked by
  P1-T15), or `failed` with `failed_step`: `authorise` (Cancel or an invalid request), `callback` (the
  token exchange failed), `discovery` (no authorize request within 15 minutes of starting),
  `first_call` (no successful call within 15 minutes of the token). The timeouts are worked out when
  the attempt is read and by the daily sweep. An approval attaches to the user's latest open attempt
  from the last 15 minutes. If there is none (someone connected from the agent without opening
  NetNet's flow), the connection is still made and `agent_connection_completed` fires with
  `entry: agent`.
- **The daily cron** `GET /api/cron/daily` (01:00 UTC, `CRON_SECRET`): the attempt timeout sweep, and
  a retry of security emails not accepted after 10 minutes and younger than 7 days. (P3 moves the
  retry into the reminder runs, per §7.10.)
- **The security email** goes through `notify()` after the response to Allow. When Resend accepts
  it, `security_email_sent_at` is set and `security_email_sent {client}` fires. The name is escaped
  and at most 40 characters, and a DCR client's name carries "(the name it gave; NetNet can't
  verify it)". It links to `/app/agent`.
- **Revocation:** `revoked_at` set, refresh tokens revoked, and an audit entry written through the
  Ledger (`withUser`, actor `user`, action `connection.revoke`). `withUser` rejects the next agent
  call (P1-T4).
- **Rate limit:** DCR 10 per hour per IP. **CIMD fetch:** HTTPS only, public addresses only (no
  private or link-local ranges), at most 5 KB, cached up to 24 hours.
- An agent's registered name never goes into an event or a log.

## Interface contract
- `/.well-known/oauth-protected-resource` (and `/.well-known/oauth-protected-resource/mcp`) and
  `/.well-known/oauth-authorization-server` per RFC 9728 and RFC 8414, with
  `client_id_metadata_document_supported: true`; `/api/auth/oauth2/authorize`, `/token`,
  `/register`, `/revoke` and `/api/auth/jwks`, the library's own paths (architecture §7.1, §7.6).
- `apps/api/src/auth/mcp-token.ts`: `verifyAccessToken(req) → {userId, connectionId, clientId,
  scopes}`, a JWT check against our JWKS (`iss`, `aud` = `${PUBLIC_ORIGIN}/mcp`, `exp`, scope) with no
  database lookup; on failure, `401` with `WWW-Authenticate: Bearer resource_metadata="…"`.
- REST (§7.2): `POST /api/agent/attempts {client, entry, platform}` → `{id, state}`; `GET
  /api/agent/attempts/:id` → `{id, state, failedStep?, cause?}`; `GET /api/agent/connections` →
  `[{id, clientName, client, registration, nameVerified, createdAt, lastUsedAt}]`; `DELETE
  /api/agent/connections/:id`.
- For P1-T15: `markAttemptLive(userId, connectionId)` and `touchConnection(connectionId)`
  (`first_call_at`, `last_used_at`).

## Done criteria
- [ ] An OAuth client test runs discovery → registration by CIMD (against a local fake metadata
      server) and by DCR → authorize → approval → token → refresh (the old refresh token is then
      rejected) → revoke.
- [ ] PKCE S256 only; exact redirect URI match; `resource` required; `iss` in the response; a token
      for another audience is rejected.
- [ ] The CIMD fetch refuses non-HTTPS, private addresses and bodies over 5 KB.
- [ ] Unverified approval → `EMAIL_NOT_VERIFIED`; Cancel → `agent_connection_failed {step:
      authorise}`; the `discovery` and `first_call` timeouts, on read and by the sweep (fake clock).
- [ ] Classification gives `claude`, `chatgpt` or `other`, and events carry only that.
- [ ] The security email: once per Allow; escaped, truncated name; the DCR caveat;
      `security_email_sent` on acceptance; a failed send retried by the daily cron.
- [ ] After revocation, the next call with a still-valid access token is rejected, and the audit
      entry exists.
- [ ] Every `/api/agent/*` route has an isolation case.
- [ ] Follows CONVENTIONS.md

Deviations:
- Outside the listed files: `db/*` (only `db/` touches `core`), `ledger/connections.ts` (the audit
  entry), `notify/*`, `origin-check.ts`, `routes.ts`, `app.ts`, the contracts (REST schemas live
  there), `playwright.config.ts`.
- `connection_attempt` gains four columns: `connection_id` (what `markAttemptLive` finds),
  `authorize_seen_at` (ends the `discovery` clock), `token_issued_at` (starts the `first_call`
  clock), `cause`. The provider needs seven tables, not §6.2's four. §6.2 and §7.2's attempts row
  now list them and `cause`'s values.
- Remembered consent off: the library has no switch. Its consent is looked up under
  `postLogin.consentReferenceId`, which is the new connection's id only inside the Allow that writes
  it (`withApproval`) and an unused value anywhere else, and the Allow deletes it. So every
  authorize shows the page, `prompt=none` gets `consent_required`, and the id rides on the code and
  refresh tokens. Side effect: the consent redirect carries `ba_pl=<Better Auth session id>` (an id,
  not the token) in the approval page's URL.
- Access tokens carry a custom `connection_id` claim, so `verifyAccessToken` returns the connection
  with no database lookup, and revocation names exactly that connection's refresh tokens.
- The library's `/oauth2/consent` is not served: Allow and Cancel go through `POST
  /api/agent/approval`, which checks the email, classifies and records the connection, then calls
  it in-process. The read also returns `client` and `host` (the CIMD URL's or redirect URI's host).
- `callback` also fails when no code exchange comes within 15 minutes of Allow (the code has
  expired), cause `timed_out`; a refused exchange is `token_rejected`. `cause` is one of
  `cancelled`, `invalid_request`, `token_rejected`, `timed_out` (contracts). "Latest open attempt
  from the last 15 minutes" counts from the later of its start and the agent's authorize request.
- Cancel with no open attempt still fires `agent_connection_failed {authorise, entry: agent}`; Allow
  with none records an approved attempt (`entry: agent`, `platform: any`) so `first_call` and `live`
  work for it. Event `client`: the guide chosen for `discovery`, the classification otherwise
  (Cancel: the refused client's).
- Exact redirect match is the library's: the exact string, except a loopback URI's port (RFC 8252;
  Codex returns to a loopback port). `resource` is required at authorize by our route. Every JSON
  answer to a browser's authorize becomes a 302, errors too (a refused CIMD client goes to
  `/app/connect/approve?error=…`), and Better Auth's `/api/auth/error` page goes there as well.
- Refresh keeps `mcp()`'s 30 s reuse window (a retry replays the same tokens); after it the old
  token is `invalid_grant` and the family is revoked. Replaying a code withdraws its tokens.
- `DELETE /api/agent/connections/:id` answers `{result: null, dataVersion, warnings: []}`;
  `dataVersion` is null for an account with no ledger, which also gets no audit entry (the audit
  hangs off `ledger_state`). `POST /api/agent/attempts` answers 201. `touchConnection` writes at
  most once a minute. `prompt=login` or `max_age` unmet → `401 REAUTH_REQUIRED`.
- Token, register, revoke, JWKS and `/.well-known`: CORS `*`, no Origin check, cookie dropped. DCR
  asking for back-channel logout is refused (the library would POST to its URL on sign-out).
- Security email: a DCR client's caveat follows the name in the subject and heading; "An agent"
  when it gave no name; a preview's captured send counts as accepted.
- Session token out of JSON bodies (the coordinator's ask): Better Auth's `hooks.after` replaces the
  sign-up, sign-in and get-session answers without `token` / `session.token`.
- New dependencies, the spike's verdict: `@better-auth/oauth-provider` 1.7.7 (the OAuth 2.1
  server, 660 KB unpacked), `@better-auth/mcp` (44 KB: the MCP resource and RFC 9728 metadata),
  `@better-auth/cimd` (72 KB: CIMD and its DNS-pinned Node transport), `jose` 6.2.12 (532 KB,
  already under Better Auth; our JWT check); `@better-auth/core` 1.7.7, `@better-auth/utils` 0.4.2
  and `better-call` 1.4.0 pinned so the lockfile keeps one `@better-auth/core`. All MIT, Better
  Auth's team (weekly releases) and panva.
