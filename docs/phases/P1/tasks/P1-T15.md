## Goal
`POST /mcp` is a stateless MCP server that Claude, ChatGPT and any standard agent can use:
authenticated by our OAuth tokens, negotiating three protocol versions, and exposing P1's sixteen
tools with schemas, annotations and structured results, all through the same Ledger as the web app.

## Context
- Read: PRD J6 (every criterion), J8 (every criterion but the M12 comparison), N1, §3.5
  (`agent_tool_called`). Architecture §3 (protocol), §5.1 (the agent read path), §7.4 (transport,
  server instructions, scopes, tools, duplicates), §7.5 (the context and the error codes), §8 (rate
  limits: 120 a minute and 5,000 a day per connection; the Prompt injection row), §10 (logs).
  CONVENTIONS §5, §9 (the REST and MCP and MCP protocol rows), §11, §12. The spike's verdict sets the
  SDK and whether to use `mcp-handler`.
- **Tools in P1** (§7.4): `get_financial_context`, `list_holdings`, `get_holding`,
  `get_net_worth_history`, `get_taxonomy`, `get_setup_guide`, `create_holding`, `update_holding`,
  `delete_holding`, `record_values`, `update_value`, `delete_value`, `upsert_type`, `delete_type`,
  `upsert_tag`, `delete_tag`. Later: `list_activity` and `undo` (P3), `get_period_changes` (P5).
- **Scopes:** reads need `ledger.read`, writes `ledger.write` (`SCOPE_REQUIRED` otherwise).
- **Every call:** `verifyAccessToken` (P1-T13) → `withUser(userId, {kind: 'agent', connectionId,
  clientName})` (a revoked connection → `401 invalid_token`) → the tool → `structuredContent` and a
  short text rendering. After the response: `agent_tool_called {tool, kind, outcome, latency_ms,
  client}`; J3's events for writes with `source: agent`; `touchConnection`; `markAttemptLive` on the
  first successful call. Leave a clearly marked hook, on `tools/call` only, where P3's
  `touchChecked` goes: `tools/list` and the handshake never count as the person checking NetNet.
- **Amounts** are decimals in major units with their currency, converted once at the boundary by
  `core.toMinor` and `core.fromMinor`.
- **Errors:** `isError: true` with `structuredContent.error {code, message, fields?}`. The message
  says what to change (J6).
- **`get_financial_context`:** `Ledger.context()` → `core.compileContext` with the pack chain and the
  user's today.
- **`get_setup_guide {country?}`:** the country's checklist and the fact questions per type, from the
  pack chain; the profile's country by default (J6's conversation assembly).
- **`create_holding`** takes `type_id` or `universal_type`, and `access_answer` (an answer id or
  `"not_sure"`); a likely duplicate returns `LIKELY_DUPLICATE`.
- User text (holding, type and tag names) appears only as JSON string values. Tool descriptions and
  the server instructions never include user data.

## Interface contract
Architecture §7.4's table: names, inputs, returns, kinds and annotations (`readOnlyHint`,
`destructiveHint`, `idempotentHint`, `openWorldHint: false`), with zod input and output schemas in
`packages/contracts/src/mcp/*.ts`. `get_financial_context`'s output schema is P1-T9's
`FinancialContext`. The server instructions are §7.4's.

## Files in scope
`apps/api/src/mcp/**` (one file per tool), `packages/contracts/src/mcp/**`, the `/mcp` route in
`apps/api/src/app.ts`, `apps/api/test/mcp/**`.

- [ ] `agent_tool_called` fires with `kind` and `latency_ms`; no amount or name in any event or log.
- [ ] A revoked connection's next call is rejected.
