# P1-T6: Core figures — money, accessibility, position, staleness, series and duplicates
Status: todo
Depends on: P1-T3 (the `Pack` schema)
Parallel-safe: yes

## Goal
`packages/core` computes every figure P1 shows or tells an agent, as pure and deterministic
functions: money conversion, accessibility from the pack chain, the position (net worth, could use,
sell first, locked, undecided, owed), staleness, the value series behind history, and likely
duplicates.

## Context
- Read: architecture §6.6 (money and FX), §6.7 (accessibility and pack versions), §7.9 (the function
  list), §7.5 (the totals the agent sees). PRD J2 (the four accessibility states: undecided counts
  toward net worth, never toward what could be used), J3 (latest by date wins), J9 (staleness
  against cadence), J11 (carried vs observed; `get_net_worth_history` needs it now). CONVENTIONS §3,
  §5, §9 (at least 90% coverage).
- Access to totals: `accessible` → `could_use`; `illiquid` → `sell_first`; `locked` → `locked`;
  `undecided` → `undecided` (net worth only). Liabilities → `owed`. Check this against the
  prototype's computation in `docs/02-prototype/app.js` and report any difference.
- Totals use each value's stored `base_minor`; nothing is re-converted at today's rate (J2, J11).
- Duplicates: normalised name similarity, same kind, same currency, compatible type; at most three
  candidates, in a deterministic order (architecture §7.4).
- The ISO 4217 minor-unit table is data in `packages/contracts` (it is not local knowledge).
- `today` and ids are always parameters. No `Date`, randomness, I/O or environment access.
- Staleness uses the holding's `cadence_days` if set, otherwise the chain's `cadenceDays[universal]`.

## Interface contract
Architecture §7.9, exactly, for `toMinor`, `fromMinor`, `convert`, `resolveAccess`, `latestValues`,
`position`, `series`, `baselineChange`, `staleness` and `likelyDuplicates`, with these additions:
- `series(values, holdings, range, interval, filter?, groupBy?)`: `interval` is `day | month |
  quarter | year`; `groupBy` is `none | type | access | currency` (architecture §7.4's
  `get_net_worth_history` needs it). Each point is `{date, total, groups?, carried}`, where `carried`
  means some holding had no observed value in that bucket.
- `baselineChange(series, baseline, today)` for PRD J4's baselines: `initial`, `last_update`,
  `last_month`, `last_quarter`, `year_start`, `last_year`.
- `packChain(packs, countryPackKey?) → Pack[]` (the country's pack then generic, or generic alone)
  and `typeLabel(chain, userType) → string` (the custom name, else the pack type's label, else the
  chain's universal label).
- The input and output types (`HoldingIn`, `ValueIn`, `Position`, `Point`, `Change`, `Candidate`,
  `AccessBasis`) live in `packages/contracts/src/figures.ts`, shared by web, API and native.

## Files in scope
`packages/core/src/**`, `packages/contracts/src/{figures.ts,currencies.ts}`, their tests.

## Done criteria
- [ ] Money: `toMinor` rejects extra precision and anything over 10¹⁵ minor units with a typed error
      naming the allowed form; `convert` is exact (BigInt inside) and rounds half away from zero;
      currencies with 0, 2 and 3 decimals are tested.
- [ ] `resolveAccess`: current pack then generic, key by key; with no question, the default and its
      reason; an answer id gives that answer's outcome; `"not_sure"` gives undecided; the basis
      carries `{via, pack, pack_version, question, answer}`.
- [ ] `position`: net worth = assets − liabilities; undecided counts toward net worth, never toward
      could use; archived holdings excluded.
- [ ] `series`: the last known value carries forward and is flagged; value dates only, never entry
      times; groups sum to the total.
- [ ] Property tests for rounding and for the position's invariants; line coverage at least 90%;
      imports limited to `contracts` and `d3-*`.
- [ ] Follows CONVENTIONS.md

Deviations:
- **Core keeps a copy of the ISO 4217 table.** Core may import only types from contracts
  (CONVENTIONS §3, lint and its test), so it cannot read contracts' table at run time. The copy is
  typed as contracts' exact table type, so any drift fails `tsc`, and a test compares the two.
- `resolveAccess` takes `VersionedPack[]` (`Pack & {version}`), not `Pack[]`, so the basis can carry
  `pack_version`. `packChain` is generic, so versions pass through it.
- `resolveAccess` returns `(Outcome | {access: 'undecided'}) & {basis}`: undecided has no reason or
  until. `basis.via` is `default`, `answer` or `undecided`; for undecided, `answer` is `not_sure`
  (said so) or null (a question left unanswered). A default is overridden by an answer to the
  chain's `other` question, which the basis records as `question: 'other'`.
- §7.9's `resolveAccess` and `convert` have no error in their types, so they throw a `RangeError`:
  an id that does not answer the type's question, and a conversion too large for a safe integer.
  `accessRule(chain, u)` gives the question (and default) to check an answer against first. Only
  `toMinor` returns an `Err` (`VALIDATION_FAILED`, `OUT_OF_RANGE`, `CURRENCY_UNSUPPORTED`).
- `staleness(holding, latest, today, chain)` takes the chain, as the brief says (§7.9 says
  `pack`). `latest` is required: a holding with no value is "without value", not stale. Stale
  means days > cadence (J9). The prototype waited for max(45, cadence × 1.6) days and called a
  holding with no value stale.
- `baselineChange` works on a series, as §7.9 has it. Today's figure is the last point on or
  before today; `initial` is the first point; `last_update` the start of the run of equal totals
  before the latest change; `last_month`, `last_quarter`, `last_year` are today minus 1, 3 and 12
  months (clamped to the month's end), `year_start` is 1 January, each taking the last point on or
  before it, or the first point when the series starts later. Nothing to compare gives nulls;
  `pct` is in percent, unrounded, and null against a zero baseline (the prototype showed 0). The
  prototype resolved baselines per holding and summed, so a holding added after the baseline did
  not count as growth; on a total series it does, and per-holding series give the prototype's
  per-holding figures.
- `series` takes `range: {from?, to}` (`from` defaults to the earliest value counted). Points sit
  at bucket ends, the last at `to`. Groups are keyed by type id, access bucket (`could_use` …
  `owed`, owed negative) or currency, in a fixed order.
- `likelyDuplicates(existing, draft, latest?)`: the optional `latest` (from `latestValues`) fills
  each candidate's `latest`, for `LIKELY_DUPLICATE {candidates: [{id, name, latest}]}`. Archived
  holdings are included. Similarity is the larger of Dice over character pairs and Jaccard over
  words of the normalised names, at least 0.6; compatible types share a universal type, or either
  is `other`.
- Extra exports beyond §7.9, so callers need no second implementation: `minorRate`, `accessRule`,
  `accessBucket`, `filterHoldings`, `chainValue`, `compareValues`, `nameSimilarity`,
  `normaliseName`, `addDays`, `addMonths`, `daysBetween`, `isCalendarDate`.
