# P1-T5: Web foundation — tokens, app shell and base components
Status: done
Depends on: P1-T1
Parallel-safe: yes

## Goal
The design system "Poster" becomes code: `packages/tokens` (both themes), self-hosted fonts, and the
`apps/web` shell (routes, layout, typed API client, the base components P1's screens need), so each
screen task only composes.

## Context
- Read: `docs/02-prototype/design-system.md` §2.1 (content rules, binding), §3 (type), §4 (colour),
  §6 (components; §6.1 hit targets, binding), §7 (layout), §8 (implementation). CONVENTIONS §13.
  Architecture §4 (the Web app row), §5.2 (the manifest; the service worker is P3's), §7.2 (the
  error body).
- **The prototype is the behavioural reference:** `docs/02-prototype/index.html`, `styles.css` and
  `app.js`; `docs/02-prototype/tests/README.md` lists the behaviour to keep. Port token values from
  `styles.css`; do not re-derive them. Both themes are authored separately (design-system §8).
- **Navigation:** the prototype's four tabs, Agent being the fourth. P1 shows Home and Agent only.
  The nav is data, so Insights (P3) and Activity (P3) are one entry each when they arrive.
- Routes without chrome (sign-up, log-in, onboarding, the approval page) switch the shell to a single
  column (design-system §7).
- Fonts: copy `docs/02-prototype/fonts/*.woff2` and `NOTICE.md` into `apps/web/public/fonts/`.

## Interface contract
- `packages/tokens`: `tokens.css` (CSS custom properties; light, and dark under
  `prefers-color-scheme`) and `tokens.ts` (the same names as a typed object, for native later). Token
  names from design-system.md.
- `apps/web/src/api/client.ts`: `api.get/post/patch/del<T>(path, body?)`, typed by
  `packages/contracts` schemas, `credentials: 'same-origin'`, turning `{error: {code, message,
  fields}}` into a typed `ApiError`. A TanStack Query provider; the `snapshot` query is keyed by
  `dataVersion` (P1-T16 uses it).
- Components, on tokens through CSS Modules: `Button` (primary, outlined, quiet; `aria-disabled`,
  never `disabled`), `TextField`, `MoneyField` (a decimal string checked against the currency's minor
  unit), `Picker`, `Sheet` (a bottom sheet on a phone, a dialog on a computer), `Rule`, `Figure`
  (money display per design-system §2.1: one figure one place, no stray cents), `Toast`,
  `ErrorState` (plain language and a next step), `Spinner`. Only what P1 needs.
- Web app manifest at `/app/manifest.webmanifest` (`scope: /app/`, `display: standalone`, icons).
- `e2e/` helpers: viewports 320, 390 and 1280 px; an axe check; a no-horizontal-scroll assertion.

## Files in scope
`packages/tokens/**`, `apps/web/**` (shell, `components/`, `api/`, placeholder routes for Home and
Agent), `e2e/` (harness and helpers).

## Done criteria
- [ ] Both themes render. No raw colour, size or font name in any component; a test scans the CSS
      Modules for raw values outside tokens.
- [ ] Layout: bottom tabs on a phone, the sidebar from 900 px, a content column whose width never
      depends on its content, the wide-screen measure of §7; chrome-less routes are one column.
- [ ] Tap targets at least 44 px (36 px with a fine pointer); nothing below 11 px on a phone; reduced
      motion honoured; only a route change scrolls to the top.
- [ ] Playwright: the shell at 320, 390 and 1280 px with no horizontal scroll; axe finds no serious
      violations; a test page shows every component in both themes.
- [ ] Follows CONVENTIONS.md

Deviations:
- Two components beyond the list: `Card` (design-system §6's primary structural device, which every
  P1 screen needs) and `Wordmark` (the sidebar's brand; sign-up and log-in reuse it).
- Tokens the design system does not name come from the prototype: `rule-strong`, `warn-bg`,
  `sun-on`, `scrim`, and type steps for controls (`button`, `link`, `field`, `amount`, `nav`, `tab`,
  `wordmark`). The chart palette (§5) is included so the poster is complete in code.
- The test page is `/app/gallery`, with `/app/gallery/no-chrome` as the chrome-less fixture. It is
  built for local, CI and preview runs and left out when `VERCEL_ENV=production`.
- `playwright.config.ts` (outside `e2e/`) gains `hasTouch` on the phone project, so the phone is
  checked against 44px targets; the E2E files reference the DOM lib, which the root tsconfig lacks.
- Back also starts a screen at the top (`history.scrollRestoration = 'manual'`), the literal
  reading of design-system §7 and what the prototype does.
- The client is typed by a generic `T` (contracts has no REST schemas until P1-T12); the error body
  is checked at runtime with the contract's `errorBodySchema`.
- `MoneyField` reports `onChange(text, check)` and reads amounts in the reader's locale; field
  errors use `attention`, since `loss` is reserved for direction (§4.1). The toast (no prototype
  reference) is an ink sticker.

Open issues:
- `money.ts` keeps its own table of ISO 4217 minor units that are not 2. Intl's CLDR data differs
  for a few currencies (IDR, MMK, LAK, IQD) and between browser and Node versions; CI's Node gave
  IDR 0 decimals. Switch it to P1-T6's ISO 4217 table in contracts, and formatting to
  `core.fromMinor`, when P1-T6 merges.
- Bundle size: zod, reached through the contract's error schema, is about a quarter of the main
  chunk. `zod/mini` in contracts, or splitting routes, would cut it if that matters.
- P1-T18: the production build must run with `VERCEL_ENV=production` (`vercel build --prod` sets
  it), and the gallery spec cannot run against production, where the gallery does not exist.
- Headless Chromium has classic scrollbars, and `scrollbar-gutter: stable` keeps their 15px
  reserved; `documentElement.clientWidth` does not report it, so layout specs measure against the
  shell's own box (see `e2e/shell.spec.ts`).
