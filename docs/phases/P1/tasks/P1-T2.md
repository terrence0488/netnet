Status: todo

## Goal
Before the real build depends on it, prove that Claude and ChatGPT can connect to a NetNet-shaped
server on Vercel and Neon in Singapore: Better Auth sign-in, its OAuth 2.1 provider with CIMD and
DCR, our own JWT check on `/mcp`, and a stateless MCP server. Write down what is true, so P1-T11,
P1-T13 and P1-T15 build on facts rather than on search results.

## Questions the spike must answer, each with evidence
1. **OAuth.** Does Claude connect by CIMD? By DCR? Which does ChatGPT use? Does Better Auth's OAuth
   provider plugin, with its CIMD package, support RFC 8707 `resource`, PKCE S256 only, RFC 9207
   `iss`, refresh-token rotation and our own approval page? If any is missing, which standalone
   OAuth 2.1 library replaces it (architecture §4's fallback), and why.
2. **Tokens.** Are access tokens JWTs we can verify in the function against the JWKS with no
   database lookup, with `aud` equal to the `/mcp` URL?
3. **MCP.** With the official TypeScript SDK (v2) in stateless Streamable HTTP, which protocol version
   does each client use today (2026-07-28, 2025-11-25 or 2025-06-18)? Does Vercel's `mcp-handler`
   help or get in the way?
4. **Latency.** From each client, 10 calls warm and 10 after five or more idle minutes (Neon waking,
   the function starting cold), against N1 (p95 under 1.5 s).
5. **Vercel Hobby.** How many cron entries does it accept, and does each start within its hour? Is
   the function region `sin1` honoured? Does any Hobby limit (duration, body size, invocations)
   block the plan?
6. **Neon.** A role created by SQL has `rolbypassrls = false` and is not a member of
   `neon_superuser`. `set_config('app.user_id', …, true)` holds for one transaction through the
   pooled connection and not beyond it.
7. **Clients.** What name each client registers and shows, the hosts its client id or redirect URI
   uses (these become `matchHosts`), and whether plan gating matches PRD §9 question 1 (record it;
   do not decide it).

## Interface contract
None for other tasks. The spike server has Better Auth email and password sign-in, a bare HTML
approval page, and `POST /mcp` with one read tool (`ping`: the user id and the server time) and one
write tool (`note`: writes one row under RLS).
