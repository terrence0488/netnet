# P1-T1: Scaffold the monorepo, CI and preview deploys
Status: todo
Depends on: none
Parallel-safe: no (every other task builds on it)

## Goal
A real, empty NetNet: the pnpm workspace in CONVENTIONS §2's layout, with lint, typecheck, tests and
build wired, CI green on GitHub Actions, and every pull request deployed to its own Vercel preview,
where `/api/health` answers and `/app` shows a placeholder.

## Context
- Read: CONVENTIONS §1–4, §7, §11, §14, §15. Architecture §4 (stack), §5.2 (one origin, rewrites,
  caching), §7.1 (URL map), §9.1–9.2 (environments, pipeline).
- Founder items first: F4 (Vercel project and GitHub secrets), F5 (network access). If they are not
  in place, build and test everything locally and in CI, and let the deploy job skip with a clear
  message rather than fail.
- **Vercel must not deploy production on a push to `main`.** Production deploys only from the manual
  workflow (P1-T18). Turn Vercel's Git deployments off in `vercel.json` and deploy previews from CI
  with the Vercel CLI (`vercel build`, then `vercel deploy --prebuilt`).
- Cloud sessions have Node 22, pnpm, Docker and Postgres 16 binaries; Chromium is preinstalled for
  Playwright (never run `playwright install`). Add a SessionStart hook (`.claude/settings.json`)
  that runs `pnpm install --frozen-lockfile`, so every build session starts ready.
- CI's Postgres is a `postgres:17` service container, matching Neon (F7).

## Interface contract
- **Root scripts** (every later task and `CLAUDE.md` use these names): `pnpm dev` (web and API
  locally), `pnpm build`, `pnpm lint`, `pnpm format`, `pnpm typecheck`, `pnpm test` (unit, every
  package), `pnpm test:int` (integration against Postgres; wired, may be empty), `pnpm test:e2e`
  (Playwright), `pnpm content:check` (a stub that passes until P1-T3).
- `apps/api/src/app.ts` exports the Hono app; `api/index.ts` re-exports it as the Vercel Node
  function. `GET /api/health` → `200 {"ok": true}` and never touches a database.
- `packages/contracts/src/errors.ts`: every code in architecture §7.5, and their HTTP statuses.
- `apps/api/src/lib/`: `AppError(code, message, details?)`; an `onError` handler mapping codes to
  statuses with the body `{"error": {"code", "message", "fields"?}}` and `INTERNAL` with a request id
  for anything unexpected; a request-id middleware; `log(event, fields)` that accepts only the
  whitelisted fields (architecture §10: request id, route, tool, status, latency, user id, connection
  id, error code) and throws on any other field outside production.
- `vercel.json`: function region `sin1`; rewrites `/api/(.*)`, `/mcp`, `/oauth2/(.*)` and
  `/.well-known/(.*)` to the function; `/app/(.*)` falls back to the web app's `index.html`; `/` is
  the landing placeholder. Headers: `Cache-Control: private, no-store` on function routes,
  `immutable` on hashed assets, `no-cache` on `index.html`; HSTS, `X-Content-Type-Options`,
  `Referrer-Policy: strict-origin-when-cross-origin`, `frame-ancestors 'none'`. The full CSP is
  P1-T18's.
- `.env.example` lists every environment variable name the code reads, never a value. Later tasks
  add theirs.

## Done criteria
- [ ] The folder layout matches CONVENTIONS §2. TypeScript `strict` with `noUncheckedIndexedAccess`
      and `exactOptionalPropertyTypes`; ESM only.
- [ ] ESLint enforces CONVENTIONS §3's import rules: `core` imports only `contracts` types and
      `d3-*`; `contracts` only `zod`; `web` never imports `apps/api`; the `ledger` schema only from
      `apps/api/src/ledger/**` (the rule exists now; its targets arrive in P1-T4). CI fails on
      warnings.
- [ ] The N10 deny-list scan (CONVENTIONS §3) runs in `pnpm test` and fails on a match outside
      `content/` and `docs/`; a test proves it catches a planted term.
- [ ] CI on every push and pull request: install (frozen lockfile) → lint → typecheck → unit →
      integration (Postgres 17) → build → E2E (one smoke test against the built app) → content check
      → `pnpm audit --prod` (fails on high or critical) → Vercel preview, its URL in the job summary.
- [ ] A preview serves `/api/health` → `{"ok": true}` and the `/app` placeholder, and `/app/anything`
      falls back to the web app.
- [ ] Vercel does not deploy production from `main` on its own.
- [ ] Renovate is configured for weekly updates (the Founder installs the Renovate app).
- [ ] `CLAUDE.md` → Commands lists the root scripts.
- [ ] Tests written and passing: the health route; the error mapping for every code; `log()` rejects
      unknown fields; the deny-list scan.
- [ ] Follows CONVENTIONS.md
