## Goal
NetNet runs on the Founder's domain from a manual, gated deploy (migrations, deploy, smoke tests,
rollback on failure), with scrubbed error reports, safe logs, strict security headers, daily
encrypted backups, and a probe of the whole MCP path every 6 hours. P1's checkpoint is reached here.

## Context
- Read: architecture §5.2 (headers and caching), §8 (the Headers and Secrets rows), §9.1–9.3 (the
  production row, pipeline step 2, the backup and probe schedules), §10, §12 risk 4. CONVENTIONS §6,
  §7, §10.
- **Founder items first:** F12 (domain, `PUBLIC_ORIGIN`, production `DATABASE_URL`), F13 (Sentry),
  F14 (backup public key), F15 (probe), F16 (uptime monitor).
- **The deploy workflow** (`.github/workflows/deploy.yml`, `workflow_dispatch` only, from a green
  `main` commit): `db:bootstrap` (idempotent) → `db:migrate` as owner → `content:publish --env
  production --strict` → `vercel deploy --prod --prebuilt` → smoke tests (`/api/health`, the OAuth
  metadata, `/mcp` without a token → `401` with resource metadata, and the probe's `tools/list` and
  `get_financial_context`) → on failure, `vercel rollback` and a failed run. Migrations are
  expand-only, so rolling back code never needs a schema rollback.
- **Sentry:** `@sentry/node` in the function, `@sentry/react` in the web app; `sendDefaultPii:
  false`; `beforeSend` drops request bodies, query strings, breadcrumb text and emails; no session
  replay.
- **CSP:** self, the self-hosted fonts, Sentry's ingest; `frame-ancestors 'none'`; HSTS.
- **Backups** (GitHub Actions, daily): `pg_dump` of `netnet-prod` (every schema) as owner, encrypted
  with `age` to `BACKUP_PUBLIC_KEY`, kept 30 days as an artifact. Write `ops/backup.md` (how to
  restore: decrypt with the Founder's key, restore into a scratch Neon branch), and run the restore
  once with a backup of fictional data.
- **The probe** (GitHub Actions, every 6 hours): one long-lived connection on a dedicated probe
  account holding fictional data. Its refresh token rotates, so the workflow writes the new one back
  to its repository secret with `PROBE_SECRETS_TOKEN` (F15). It must never create a connection per
  run: each connection sends a security email and uses Resend's 100 a day. Write the one-time setup
  for the Founder (create the account, approve the connection) into `ops/probe.md`.
- **From the spike** (`docs/phases/P1/spike.md` Q4, Q5): Vercel runs crons only on production, so
  their timing is checked here. Hobby states "per-hour (±59 min)"; if a cron starts outside its
  hour, take §9.3's GitHub Actions fallback and record it in `docs/decisions.md`. Each probe call
  comes after hours of idle, so the probe logs its calls' client-observed time next to the
  function's `latency_ms`: the production measure of the first call after idle.
- **Before launch, `/` stays a plain holding page** (P4 builds the landing page).
